# Серверная разметка книг и персонажи

Основание: пользовательский контракт `ios-book-markup-characters-backend-contract.md`, 28.08.2026. База `7c4cce47274909b8f871abb5e0b0388d6bc71fd2`; изменения выполнены в worktree `/Users/manaer/.codex/worktrees/5652/Narra2`, исходный checkout не изменялся.

## Что изменилось для пользователя

- Каталожные книги используют готовую серверную разметку. Открытие не запускает локальный анализ, регистрацию, загрузку исходника или генерацию портретов.
- После импорта собственной книги приложение ищет её по SHA-256. Найденная каталожная книга переиспользуется; частный исходник передаётся серверу один раз. TXT/UMD сохраняют оригинальные байты до преобразования в EPUB.
- Чтение не ждёт серверного названия, разметки и картинок. Название уточняется независимо; ошибки не удаляют последний готовый набор персонажей.
- Подтверждённый персонаж доступен для чата без портрета. Временный персонаж показывается отдельно, без действия; в постоянный список, историю и кликабельные имена он не попадает.
- Персонажи появляются по прочитанному месту и сохраняют серверный порядок. Характер берётся из последнего достигнутого снимка, без будущих черт.
- Портрет, приветствие и анимация скачиваются только для достигнутых персонажей. Файлы проверяются по размеру и SHA-256. Одновременно обрабатываются не больше двух персонажей; одна ошибка не убирает профиль. Ручной портрет сохраняет приоритет.
- Прогресс отправляется с объединением за 1,5 секунды и максимумом внутри серии. Опрос разметки не повторяет загрузку исходника. Неопределённый результат прошлой загрузки сначала перепроверяется через resolve.
- Автоматическое создание отсутствующих обложек при импорте отключено, чтобы не запустить его до результата resolve-to-catalog. Встроенная обложка файла и стандартная заглушка остаются.

## Фактические особенности ответа сервера

Сырые публичные каталожные данные — `catalog-live.json`. Это данные каталога, не пользовательский файл; токены и подписанные URL не сохранялись.

- Реальное поле — `profile.personalitySnapshots`, с `cutoffTextOffset` и массивом объектов `traits[].value`. `profile.traits` содержит итоговые черты и **не используется**, когда есть временная шкала, но ещё нет достигнутого снимка.
- У проверенного manifest отсутствует `markup.revision`, `reading_fraction` равен null. Парсер принимает их отсутствие; сохраняются publication ID и content hash.
- Приветствие имеет MIME `audio/wav`; сохраняется с расширением WAV.

## Ограничения и риски

- Собственная книга на реальный backend не загружалась: resolve/register/upload/identity/processing/ready проверены изолированными тестами. Полный живой private-сценарий остаётся непроверенным.
- После явного импорта серверная подготовка запускается в фоне; этот временный потребитель прекращается при ошибке/готовности или через две минуты. Открытая книга продолжает обработку через своих потребителей; при следующем открытии синхронизация возобновляется.
- Для старых TXT/UMD, преобразованных до этого изменения, исходные байты восстановить нельзя: сервер получит имеющийся локальный EPUB. Новые импорты сохраняют оригинал.
- Старые локальные персонажи больше не подставляются по названию. Старые сообщения физически не удаляются, но автоматическое сопоставление прежних локальных ID с серверными `character_key` не выполняется: объединять разные личности по одному имени небезопасно.
- Native/Release/физическое устройство не пересобирались и не проверялись. Новые замеры скорости/памяти не выполнялись; снижения памяти не заявляется.
- При первой диагностической CDP-сессии завершился прежний процесс PID 11313: EXC_BAD_ACCESS/SIGSEGV, верхние кадры Hermes CodeBlock → Debugger (13:29:38 UTC). Это тот же участок стека, что встречался до этой задачи; причинность подключения не доказана. После штатного запуска wrapper процесс PID 26581 прошёл живые проверки. Нативный код не менялся.
