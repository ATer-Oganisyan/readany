# Очистка каталога и блокировка внешних страниц

Клик по «сюртуке» в настоящем EPUB «Бригадира» открывал `ru.wiktionary.org`: Foliate вызывал `window.open`, если обработчик `external-link` не отменял действие. Мобильная оболочка такого обработчика не имела. Теперь событие отменяется, а WebView дополнительно ограничивает навигацию локальной читалкой. Переходы по главам и авторским сноскам сохраняются.

## Состав изменения

- Один XML-парсер вместо прежней очистки EPUB регулярными выражениями. Он обслуживает и встроенные книги, и выгрузку серверного каталога.
- Убираются внешние ссылки, формы, скрипты, шапки сайтов, подписи оцифровщиков, издательская реклама, проверенные редакторские вступления и комментарии. Слова внутри ссылок остаются обычным текстом.
- Авторские предисловия, посвящения, эпиграфы, примечания и художественные «предисловия издателя» сохраняются. Неоднозначные заголовки `PREFACE`/`INTRODUCTION` удаляются только по проверенной привязке к конкретному исходнику, файлу и заголовку в `scripts/catalog/reviewed-sections.json`. Для смешанных документов заданы границы, после которых начинается авторский текст.
- Названия и авторы EPUB приводятся к карточкам каталога. Метки оглавления очищаются от HTML и лишних пробелов; ссылки на удалённые разделы убираются, вложенные главы сохраняются.
- Заголовки глав и названия в NCX/NAV приводятся к регистру предложения: первая буква заглавная, последующие строчные. Римские номера сохраняются: `* ДЕЙСТВИЕ II *` → `Действие II`. Служебные звёздочки удаляются. Если пункт оглавления состоял только из звёздочек, он получает `Раздел N` / `Section N`; авторские разделители между сценами вне оглавления сохраняются. Нормализуется текст в существующих узлах, без удаления идентификаторов, вложенной разметки или адресов. Оформление, принудительно включавшее капс/капитель, отключается на заголовках. Это применяется и к экспортам без явного `<body>`.
- Повреждённый XML восстанавливается только при сохранении всех текстовых узлов и идентификаторов. Если восстановление теряет текст, обработка завершается ошибкой.
- Для «Сказки о царе Салтане» по проверенной привязке к исходнику снято обтекание иллюстраций: на мобильной ширине оно сжимало стихотворные строки до одного слова. Изображения и стихотворный текст сохранены.
- Имена файлов глав и порядок элементов `spine` не меняются. Служебные и опустевшие разделы получают `linear="no"`. Атрибуция и лицензии сохраняются внутри архива вне порядка чтения. Gateway теперь также исключает нелинейные разделы из текста для разметки.

## Воспроизведение полной очистки

Снимок `scripts/catalog/catalog-snapshot-2026-09-11.json` содержит 1503 действующих издания: 504 русских и 999 английских. Это метаданные обычного читательского API; токенов и подписанных ссылок в файле нет. Для каждого исходника зафиксирован SHA-256. Если данные изменились, очистка остановится до выпуска нового манифеста.

Из корня репозитория:

```sh
python3 -m pip install -r scripts/catalog/requirements.txt
# sources/<book_edition_id>.epub — исходные файлы из снимка.
python3 scripts/catalog/clean_catalog.py \
  scripts/catalog/catalog-snapshot-2026-09-11.json sources cleaned
python3 scripts/catalog/verify_catalog.py \
  scripts/catalog/catalog-snapshot-2026-09-11.json cleaned/books verification.json
node scripts/catalog/verify_catalog_extraction.mjs \
  scripts/catalog/catalog-snapshot-2026-09-11.json cleaned/books extraction.json
```

`cleaned` содержит книги, `manifest.json`, подробный `report.json` и итоговый `summary.json`. Исходники не перезаписываются. Неизменившиеся книги сохраняют исходные байты; повторная очистка проверяется на полное совпадение результата.

При отсутствии локальных исходников их можно скачать обычным читательским токеном:

```sh
# NARRA_READER_TOKEN задаётся в окружении, не записывается в репозиторий.
python3 scripts/catalog/fetch_catalog.py \
  scripts/catalog/catalog-snapshot-2026-09-11.json sources \
  --base-url https://api.narra.disrupt.builders
```

Скачивание ограничено по частоте, повторный запуск пропускает уже проверенные файлы. При истечении токена нужно обновить его и повторить команду. Скрипт использует только читательский маршрут скачивания; административных запросов нет.

Встроенные 17 EPUB уже обновлены в `packages/app-expo/assets/catalog`. Команда `pnpm --filter @readany/app-expo clean:catalog-books` использует тот же обработчик; `PYTHON` позволяет указать интерпретатор с установленным `lxml`.

## Публикация каталога разработчиком

PR сам ничего не выкладывает: не меняет Docker-образы, контейнеры, серверное хранилище или БД. Слияние кода приложения и замена серверных изданий — отдельные действия разработчика.

Изменённый EPUB — новое издание с новым хешем. Нельзя перезаписывать объект старого издания или переносить старые смещения разметки на новый текст. В `manifest.json` для каждого результата указаны новый `catalog_key`, хеш, исходные `book_edition_id`/`catalog_key`/хеш, жанры и сведения об исходной обложке.

Порядок применения:

1. Выполнить проверки на файлах и испытать новые издания в тестовой среде со свежим gateway. Загрузить новый EPUB через существующий каталоговый upload/complete API и дождаться новой разметки.
2. Перенести прежнюю обложку через существующий cover upload API, сохранив её хеш. Перенести жанры в `book_edition_genres` и соответствие рейтинга в `catalog_book_popularity_aliases`. Проверить название, язык, обложку, жанры и готовность новой разметки. Поля `replaces` и `genres` в манифесте служат исходными данными для этой операции: старый `seed-book-catalog.mjs` сам их не переносит.
3. После проверки скрыть старую каталожную карточку через существующий `hideReplacedCatalogBook` с парой старого и нового ID. Этот метод требует готовую публикацию разметки, одинаковый язык/название и разные хеши. Старое издание и пользовательские ссылки на него сохраняются.
4. Применять замену партиями. При ошибке оставить старое издание видимым; не удалять его исходник. Для отката видимости восстановить `catalog_hidden_at` и `replaced_by_book_edition_id` из снимка перед заменой, скрыть новую карточку. Пользовательские заметки и прогресс не перепривязывать автоматически.

DDL не требуется: механизм замен уже есть в миграции `021_catalog_replacements.sql`, жанры — в `016_book_genres.sql`, рейтинг — в `022_catalog_book_popularity.sql`, обложки — в `004_catalog_covers.sql`. Данные изменяются только при отдельном применении новых изданий. Старые клиенты продолжают открывать свои старые издания; обновлённая читалка блокирует внешние страницы и в уже скачанных книгах. Для полного исключения служебных страниц из новой разметки gateway с поддержкой `linear="no"` должен быть установлен до запуска анализа замен.

## Регрессионные проверки

```sh
python3 scripts/catalog/audit_catalog_content.py \
  scripts/catalog/catalog-snapshot-2026-09-11.json cleaned/books visible-content-audit.json
python3 scripts/catalog/audit_chapter_headings.py cleaned/books headings-audit.json
python3 -m unittest discover -s scripts/catalog -v
pnpm --filter @readany/app-expo exec vitest run src/lib/reader
node --test services/narra-gateway/test/book-source-text.test.mjs
# Требует Playwright и Chromium; воспроизводит баг на настоящем EPUB.
node packages/app-expo/scripts/verify-reader-external-links.mjs
node packages/app-expo/scripts/verify-cleaned-catalog.mjs cleaned/books reader-screenshots
```

Браузерный тест использует собранный `reader.html` и исходный EPUB «Бригадира». Контрольный вариант без обработчика делает один вызов `window.open`; исправленный — ноль. Оба варианта после нажатия перелистывают книгу. `window.open` перехватывается, поэтому тест не обращается к Викисловарю. Мост React Native заменён сборщиком сообщений: это проверка настоящего браузерного движка читалки, не запуск нативного эмулятора.

Существующий workflow gateway запускает его регрессионные тесты на pull request. Проверки полного каталога и браузерные сценарии воспроизводятся командами выше; новый workflow не добавлен.

Независимый `audit_catalog_content.py` использует стандартный XML-парсер Python и не импортирует код очистки. Он отдельно просматривает каждый читаемый документ: внешние переходы, видимый HTML, адреса сайтов и подписи экспорта. Найденные подписи проверяются по содержанию; приёмочный отчёт должен содержать ноль неподтверждённых находок.
