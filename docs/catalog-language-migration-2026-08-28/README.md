## Что изменилось

- Поле `language` сохраняется в каталоге, дисковом кэше v2, binding и manifest.
  Отсутствие поля и null означают неизвестный язык; старые кэши продолжают читаться.
- При импорте язык из EPUB/другого поддерживаемого парсером файла теперь попадает
  в библиотеку: прежде парсер извлекал его, но обычная ветка импорта теряла поле.
- Регистрация пользовательской книги передаёт известный базовый код языка
  (`EN_us` → `en`, `ru-RU` → `ru`). Неизвестное значение не отправляется.
- Язык из серверного каталога сохраняется при импорте. Старый/null ответ не
  стирает известный язык локальной книги. Язык не угадывается по названию,
  автору, catalog_key или языку интерфейса.
- Добавлен `fetchBackendLanguageCatalogPage("ru" | "en", cursor?, limit?, signal?)`
  для `/v2/books/catalog/languages/:language`. Проверяются версия
  `book-catalog-language-v1`, язык верхнего уровня и каждой книги, готовность
  и курсор. Несовместимая языковая страница не публикуется частично.
- Для all/ru/en отдельные экземпляры store, курсоры, поколения и дисковые
  журналы. Языковые кэши находятся под `book-catalog-language-v1/ru|en`,
  старый общий путь не изменён. Отмена одного потребителя не отменяет чужой каталог.
- Общий cover cache сохраняет обложки, используемые любым загруженным каталогом;
  завершение загрузки обложки не меняет metadata.

## Интерфейс и границы

Существующие Library/Search/подборки продолжают использовать общий каталог.
Новых вкладок «Русские/Английские» и фильтра по языку интерфейса не добавлено.
Для отдельной языковой поверхности готов `useBackendCatalog(active, "ru" | "en")`
и соответствующий `useBackendCatalogActivity`. Языковые store создаются лениво:
обычный экран не начинает дополнительно скачивать оба языка.

Admin ingest, сервер, настройки endpoint, native-код и зависимости не менялись.
Commit/push/merge не выполнялись. Пользовательская библиотека не очищалась.

Доступный установленному приложению английский endpoint сейчас отдаёт только 3.
Это наблюдение ответов сервера; причина расхождения не установлена, полнота
заявленных 1503 книг/503 русских не подтверждалась и миграция данных не выполнялась.
Клиент не подменяет этот ответ общим каталогом и не скрывает расхождение.

В первой диагностической попытке была ошибочная проверка «на второй странице
обязательно две книги». Валидная последняя страница en из одной книги её не прошла.
В приложении такого ограничения нет. Raw сохранён как `native-api-first-attempt.json`;
`native-api-diagnostic.json` показывает причину, `native-api.json` — финальную
проверку с допустимой неполной последней страницей. Файлы не переименовывались
в успешные задним числом. JSON-поле `error` проверено отдельно от exit code helper.

Скрипт `native-api-probe.js` выполняет только чтение каталога. Содержимое книг,
токены и регистрационные секреты в отчёт не записаны. Исходные диагностические
ID относятся к каталожным edition, нужны для проверки отсутствия дублей.
Логи проверок и SHA — рядом. Время тестов в `.txt` — Europe/Moscow, JSON — UTC.
