## Результат для пользователя

Книжный плеер теперь получает озвучку от SaluteSpeech через Narra Gateway.
Каждое предложение отправляется отдельно, с выбранным голосом рассказчика или
персонажа. Сохранены чтение с текущего места, локальное определение реплик,
ударения, очередь предложений и существующая синхронизация с текстом.

| Область | Было | Стало |
|---|---|---|
| Провайдер книжного плеера | Общая настройка Narra по умолчанию выбирала прямой Grok | Отдельный книжный вызов `/v2/speech/synthesize`, не зависит от общего провайдера |
| Скорость | Для Grok менялась на устройстве | Передаётся через SSML; TrackPlayer остаётся на 1×, без двойного ускорения |
| Изменение скорости на паузе | Существующая ветка resume могла продолжить прежний файл | При возобновлении изменённые параметры пересинтезируют текущий фрагмент; сама настройка не снимает паузу |
| Остановка | Устаревший запрос мог продолжить скачивание | Отмена транспорта и ожидания повторов; поздний файл удаляется |
| Сбой сервиса | Не все терминальные ошибки различались; в лог мог попасть текст | Ограниченные повторы временных ошибок, немедленная остановка при AUTH/CONFIG/REQUEST, безопасный код ошибки без текста |
| Ответ сервера | Прежний общий маршрут | Проверка MIME, частоты, RIFF/WAVE-сигнатуры, размера и сохранённого файла до передачи плееру |

Настройки других TTS-движков сохранены. Озвучка чатов/сцен остаётся на прежнем
общем маршруте. Новых компонентов интерфейса, зависимостей, backend endpoints,
native-изменений и серверных публикаций нет.

## Что уже соответствовало документу

- Извлечение предложений и CFI из EPUB выполняется локально, не сервером.
- Voice plan и назначение голосов остаются локальными; LLM на каждую реплику не добавлен.
- Подача текста: 72 предложения, пополнение при остатке 18, следующая глава до 500;
  отдельная выборка для прогресса до 10 000 не означает синтез всего этого текста.
- До трёх запросов синтеза параллельно, стартовый буфер до восьми сегментов,
  сохранение порядка и существующий тихий keep-alive TrackPlayer.
- Installation auth и однократное обновление токена при соответствующем 401 —
  через существующий общий сетевой слой.

## Реализация и защита от ошибок

`synthesizeNarraBookSpeech` отправляет только `{text, voice}` либо `{ssml, voice}`.
Book ID, CFI и контекст книги в endpoint не добавлены. Применяется существующий
словарь ударений и SSML-просодия, текст ограничен 12 000 символов, SSML — 24 000.
Общий deadline 60 секунд охватывает авторизацию, заголовки, body и сохранение.
Аудио читается потоком с пределом 16 MiB. Допускаются WAV 24/48 kHz; проверка
сигнатуры не является полным декодером/валидатором всех WAV-чанков.

При временной ошибке максимум пять попыток получения сегмента с отменяемыми
паузами 500/1000/1500/2000 мс. После исчерпания — Stop и очистка. Независимая
генерация сессии не даёт завершению старого запроса остановить новую сессию.
Проверки после асинхронного сохранения удаляют поздние/неполные файлы.

## Ограничения и риски

- Реальный SaluteSpeech, качество/произношение, задержка, действующие лимиты
  deployment и стоимость не проверены: платных запросов не делали.
- Нет готовой аудиокниги, серверного аудиокеша или скачивания для офлайна.
  Повторное чтение и изменение скорости могут оплачивать синтез повторно.
- Русские эвристики говорящего сохранены, могут ошибаться; английские реплики
  не получают нового алгоритма атрибуции.
- Сверхдлинное предложение по контракту обрезается до 12 000 символов.
- Неизвестный обычный `character.voice` отклоняется backend; новый fallback
  для такого случая не добавлялся.
- CFI, переход главы, фон/заблокированный экран, физический телефон и Release
  не проходили новый полный UI-прогон. Данная нативная проверка — controller/audio
  integration, не полный пользовательский сценарий «кнопка → речь → следующая глава».
- Удаление временных файлов подтверждено на Stop; уборка сирот после аварийного
  завершения процесса и длительный memory/дисковый stress не входили в проверку.

Следующая пользовательская проверка: открыть книгу и нажать «Слушать», чтобы
проверить уже настоящее звучание сервиса на своём тексте.
