## Что меняется для читателя

- Встроенная сцена для привязанной книги запрашивается по редакции и позиции. Текст страницы, prompt, модель и персонажи больше не отправляются с телефона в эту генерацию.
- Нажатие фиксирует позицию до первого ожидания. Перелистывание не переключает текущий запрос на другую сцену; повтор после ошибки и повторного открытия книги использует сохранённую позицию.
- Очередь опрашивается до пяти минут по времени, с серверным интервалом (по умолчанию 2 секунды, минимум 250 мс). После срока — один дополнительный recovery-запрос. HTTP-запрос и native download имеют отдельные 60-секундные ограничения.
- Ошибка скачивания приводит к новому запросу свежей ссылки, а не к повторному использованию истёкшей. Серверный `failed` и постоянные 400/404/409/422 завершают попытку; ошибки не запускают legacy-генерацию для привязанной книги.
- В store попадает локальный непустой файл, после чего data URI отправляется в WebView. При повторном открытии сохранённая сцена читается локально. Незавершённая сцена восстанавливается как кнопка повтора, без автоматической генерации.
- Закрытие читалки отменяет клиентские запросы; уход приложения в background не отменяет серверную работу и polling-действие.
- Убрано обещание «20–60 секунд»: «Это может занять несколько минут» / “This may take a few minutes”.
- Диагностика объединяет этапы одним случайным ID и фиксирует позицию, безопасные идентификаторы, этап, MIME/байты и состояние приложения. Ни signed URL, ни содержимое книги, ни токены в журнал не попадают.

Визуальная карточка, её квадратный формат и существующий loader сохранены. Ручная генерация по выделенному тексту остаётся отдельным прежним сценарием.

## Результат ревью

Исходная встроенная сцена использовала видимый текст и `generateNarraSceneImage` с legacy fallback. Backend-пути `/scenes/at`, устойчивого snapshot позиции и восстановления fresh URL не было. Сохранение выполнялось до проверки пригодности файла.

В этой версии репозитория отсутствуют серверные файлы из контракта (`book-catalog-api.mjs`, `book-catalog-service.mjs`, `postgres-book-markup-repository.mjs`, `book-scenes.mjs`). Поэтому изменения worker/очереди и проверка серверной идемпотентности не выполнялись. Клиент никогда не вызывает новый endpoint из открытия книги, progress или manifest.

Контракт не передаёт версию разметки в POST: клиент хранит локальную identity для файла, но сервер остаётся владельцем расчёта слота/актуальной версии. Проверка отсутствия дублирующих jobs требует доступа к актуальному backend и его тестам. Ручной legacy в этом checkout также отличается от названного в документе `/v2/media/scene/jobs`; его API-контракт не предоставлен, в эту миграцию он не включён.

## Найденная при ручной проверке ошибка и исправление

Пользователь запустил сцену в установленном Debug dev-client. Локальный журнал показал `ready → download → move → retry`, без `store`/`webview`. Файл на диске уже существовал, размер 111854 байта (backend объявляет image/png).

Причина первой реализации: в установленном Expo `File.move()` возвращает `Promise<void>`, а код не ожидал его перед проверкой итогового файла и очисткой временного пути. Исправлено на `await temporary.move(destination)`. Первоначальный mock был синхронным и скрывал эту гонку; теперь mock асинхронный, проверяет сохранность результата после cleanup. Также учитывается изменение URI самого File после move: очистка обращается только к первоначальному временному пути.

`manual-before-move-fix.json` — реальные события неудачной пользовательской проверки, не успешная приёмка. Fast Refresh остановил старое действие, поэтому для проверки новой версии потребовалось повторное открытие книги и нажатие Retry. Нативная пересборка не выполнялась.
