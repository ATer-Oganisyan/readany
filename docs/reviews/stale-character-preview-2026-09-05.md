# Предварительные персонажи прежней редакции

Три регрессии воспроизвели публикацию запоздалого preview после смены edition, смены SHA при том же edition и удаления книги. Готовые профили имели проверку requestIdentity, но промежуточный список обходил её.

Теперь `BackendBookSession` передаёт в publishPreview соответствующий запросу manifest. Sync использует его зафиксированную requestIdentity для проверки текущего binding и проверяет наличие неудалённой книги перед обновлением UI-status. Старые персонажи не публикуются и не очищают ошибку текущей книги. Существующая проверка run ID сохраняется.

Проверки: исходно 3 FAIL / 44 PASS; после исправления sync/session 64 PASS, TypeScript PASS; полный мобильный прогон 177 файлов / 1654 теста PASS. Штатный переход preview → готовый manifest остаётся покрыт существующим поведенческим тестом.

Использован Expo native-data-fetching для проверки актуальности асинхронного ответа. Сеть в тестах управляемая, настоящие sync/session/store; на устройстве сценарий не проверялся. Исправление не отменяет старый запрос и не очищает уже показанный preview непосредственно в момент внешней смены binding. Полный lifecycle сессии и переход A→B→A остаются отдельной областью приёмки.
