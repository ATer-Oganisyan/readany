# Заметки из открытой книги: закрытие, создание и привязка

## Воспроизведённые дефекты

- На iOS книжный блокнот открывался модальным экраном без Close/Back:
  [исходный экран](evidence/ios-2026-09-05/notes-no-close-before.png).
- Редактор новой заметки тоже не имел Cancel/Back; у пустой заметки Save
  отключён, оставался только жест закрытия:
  [исходный редактор](evidence/ios-2026-09-05/note-editor-no-cancel-before.png).
- Root создал собственную QA-заметку из Reader → Notes → Add note. UI показал
  результат, но фактическая SQLite-запись получила `book_id = NULL`.
  Empty-state Add не передавал `bookId` в маршрут редактора.
- Mounted `NotesView` дополнительно воспроизвёл потерю книжного контекста при
  blur/возврате и подмену пустого блокнота текущей книги глобальными заметками
  других книг.
- После первой записи книжная detail-ветка не содержала Add note, поэтому
  повторное создание через этот экран становилось недоступным.
- Отложенный UPDATE существующей заметки закрывал редактор до подтверждения
  SQLite. Отказ записи только логировался, а UI продолжал показывать
  несохранённое изменение. Встроенный редактор также закрывал черновик раньше
  результата.
- Ввод во время сохранения мог потеряться после успешного закрытия; два
  вызова одного native Save callback до rerender создавали два запроса.
- Завершение INSERT для книги A после переключения на B добавляло заметку A
  в текущую коллекцию B. Аналогично запоздалый load A мог заменить результаты
  нового load B. Это смешивание книг одного пользователя, не аккаунтов.

## Изменения

`FullScreenNotesScreen` использует существующие native header actions:
на iOS Add и Close, на Android существующий `NativeButton` Add справа с
неизменённой навигацией назад. Add всегда передаёт `bookId` текущей книги;
доступен и в пустом, и в непустом блокноте.

`ManualNoteScreen` получил iOS Cancel слева. Пустая или неизменённая заметка
закрывается сразу; изменённый текст, удаление исходного текста или смена книги
у непустой заметки требуют подтверждения Keep editing/Discard. Во время
сохранения Cancel отключён. Выбор книги и Save справа сохранены. Тексты
подтверждения добавлены в EN/RU, контрольная сумма словаря обновлена.

`NotesView` передаёт выбранную книгу из empty-state Add, сохраняет исходный
книжный scope при возвращении из редактора и не показывает чужие заметки
вместо пустого блокнота. Глобальное создание без книги и редактирование
существующих записей сохраняют прежнюю маршрутизацию.

Сохранение новых/изменённых заметок теперь публикует результат только после
успешной записи. Очередь сериализует запись и обновление производных данных;
отказ возвращается редактору, не блокируя последующую попытку. Старые
fire-and-forget вызовы имеют внутренний обработчик отклонения, тогда как
ожидающий редактор получает исходную ошибку. Ошибка производного чтения после
успешной записи не выдаётся за отказ самой записи.

ManualNote сохраняет id и базовый текст уже записанной заметки. Если пока
шла запись пользователь изменил текст или выбранную книгу, редактор остаётся
открытым, следующий Save обновляет тот же id. Синхронный single-flight guard
защищает от двойного вызова Save. Inline NotesView тоже ждёт запись, оставляет
черновик при отказе и не закрывает более новый ввод по завершении старого Save.

Коллекции Reader привязаны к активной книге с начала загрузки. При смене
книги старые overlays очищаются; generation guard не допускает публикации
устаревшего запроса. Отложенные записи публикуются только в подходящий scope.
Глобальная `highlightsWithBooks` для общего блокнота остаётся глобальной.
Дополнительный фильтр Reader по `bookId` защищает все его потребители даже
при получении смешанной коллекции. Фильтр меняется и при смене route bookId,
без обязательного обновления store.

Миграции и ретроспективного изменения сохранённых заметок нет. Ранее созданная
собственная QA-запись с `book_id = NULL` намеренно не перепривязана.

## Границы приёмки

Root/iOS выполнил функциональный AFTER: две собственные заметки из одной
книги, Add после первой записи, пустой Cancel, dirty Keep editing/Discard,
Close и возврат к точному CFI. [Фактические SQLite строки](evidence/ios-2026-09-05/notes-book-association-after.json)
содержат два разных новых id с правильным `book_id`; прежняя QA-запись с NULL
сохранена без изменений.

Этот проход выявил отдельное перекрытие вкладок прозрачным iOS header и
пустую строку цитаты у ручных заметок. Root добавил scoped header inset,
локализацию служебного названия раздела и отсутствие пустой цитаты, с
поведенческими регрессиями. [Нативный iOS AFTER визуальных исправлений](evidence/ios-2026-09-05/ios-notes-layout-after.png)
пройден: заголовок отдельно от вкладок, `Book note` в EN, пустых цитат нет,
Edit/Delete доступны, Close возвращает к чтению. Нативный AFTER последних
Save/scope guards и Android Notes ещё выполняется.
Инъекция ошибки SQLite проверена deferred DB tests, не повреждением
пользовательской нативной БД.

Подтверждение несохранённых изменений относится к новой кнопке Cancel.
Защита всех способов закрытия, включая нативный swipe-dismiss и системные
жесты, этим ограниченным изменением не заявляется. Durable draft persistence
между перезапусками приложения не добавлен. Legacy notes/bookmark/delete
операции не объявляются полностью переведёнными на acknowledged saves.

## Адрес заметки из выделения PDF

Финальный iOS-проход выделил `diary` на Page 4 исходного PDF и сохранил
собственную заметку. SQLite содержал правильные `book_id`, текст и название
страницы, но пустой `cfi`. Причина найдена до слоя сохранения:
`FixedLayout.getContents()` возвращал `{doc}` без `index`; `emitSelection`
вызывал `View.getCFI(undefined, range)`, и его перехваченная ошибка превращалась
в пустой адрес.

FixedLayout теперь хранит индекс настоящего iframe и возвращает его вместе
с документом; пустые половины разворота исключены. Для fixed layout сохраняется
устойчивый CFI страницы, например `epubcfi(/6/8)` для Page 4. PDF text layer
пересоздаётся при масштабировании, поэтому точный постоянный адрес выделенного
слова не обещается. Reflowable EPUB по-прежнему использует точный Range CFI.
Адрес берётся из выбранного документа разворота, а не из primary page.

Расширенный `fixed-layout-lifecycle.test.ts` исполняет настоящие FixedLayout,
`emitSelection`, методы View и модуль CFI. Три RED → GREEN: пустой адрес Page 4,
индекс выбранной стороны разворота и blank-frame metadata. Reflow Range —
неизменённый positive control; весь файл **7/7 PASS**. Проверены resolve в другую страницу
и назад, а также отсутствие вызова text-range/overlayer при page-note:
страница не закрашивается целиком.

Page-only CFI не различает два выделенных фрагмента одной страницы. Настоящие
Reader callbacks воспроизвели две коллизии ключа сохранённых summary/scene
(2 RED → 5 PASS). Bridge явно передаёт `cfiGranularity`; только для page-anchor
локальный ключ дополнен стабильным 64-битным отпечатком всего выделения и его
длиной. Повтор того же выделения даёт тот же ключ, разные фрагменты после первых
120 символов различаются. Это не криптографическая гарантия идентичности данных.
CFI заметки остаётся адресом страницы; reflow/старые range-ключи не изменены.
Два дополнительных теста прогоняют helper через настоящий Expo/Babel pipeline
для iOS/Android и исполняют ключи с кириллицей/emoji. Весь соседний набор:
**6 suites / 72 PASS**, app TypeScript PASS, Biome новых
тестов PASS. Полный lint ReaderScreen по-прежнему сообщает существующие hook
dependency diagnostics; они не объявлены исправленными этим узким изменением.

Root независимо проверил page-index/granularity/no-overlay/sourceKey и прогнал
37 соседних тестов. Reader bundle собран официальным Node 24, SHA256 HTML:
`8a06cd1a125f9fa1b17b94d8759f4e28916cc28a29a594173de6ebac5221cf90`.

Нативный iOS AFTER **PASS**: root выполнил полный Maestro-сценарий
`2026-09-05_130646` на этой сборке. Выделение `diary` на Page 4 → новая заметка
`NARRA QA PDF page anchor 20260905.` → Page 5 → Notes → заметка → Page 4.
Новая запись `17e38a58-c3da-4f8c-a4fc-0326ec87e12f` относится к правильной
PDF-книге и содержит `cfi = "epubcfi(/6/8)"`. Проверены и видимая четвёртая
страница после возврата, и сохранённая запись; страница целиком не закрашивается.
