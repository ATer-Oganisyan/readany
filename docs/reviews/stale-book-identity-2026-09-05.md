# Запоздалое имя книги после замены исходника

Воспроизведение на реальном sync/store с управляемым ответом HTTP: начать identity-запрос редакции A, переключить binding на B, завершить A. Старый успешный ответ менял название B, старый failed-ответ записывал `identityError`. Оба новых теста упали до исправления.

Исправление: identity-запрос фиксирует edition и SHA, проверяет текущую привязку и наличие неудалённой книги перед запросом и перед применением ответа. Ошибка сети от уже неактуальной редакции не публикуется. Добавлен третий тест с rejected-запросом. Подход соответствует Expo native-data-fetching: проверка актуальности результата вместе с отменой, без изменения провайдеров или новых повторов.

Проверки: targeted sync/session 57 PASS; `pnpm exec tsc --noEmit` PASS; полный `pnpm test` — 176 файлов, 1640 тестов PASS. Native UI в этой проверке не запускался.

Границы: это не полная защита всех стадий импорта. Отдельный аудит воспроизвёл stale-cover после замены книги и позднюю запись binding A поверх B из `bindBook`; эти дефекты ещё требуют исправления. Preview/error callbacks других операций и переход A→B→A остаются отдельной областью проверки. Нельзя считать весь путь замены исходника принятым по этим трём тестам.
