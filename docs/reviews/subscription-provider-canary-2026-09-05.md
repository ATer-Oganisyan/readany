## Область проверки

`scripts/qa/codex-provider-canary.mjs` использует настоящий `requestChat`
gateway. Сначала без сети получает точную сериализацию запроса для списка
разрешённых SHA256; этот предварительный ответ `capture-only` не является
генерацией и не засчитывается как успех провайдера.

Затем `--live` допускает ровно один запрос к локальному bridge через обычный
LiteLLM-compatible путь. Вход — собственный короткий рассказ об Анне и Льве,
не пользовательская книга; ожидаются JSON, два точных имени и краткий пересказ.
SHA256 тела: `9fac970ca53225b2b7ee5a2727c367afd5c1471897072f0253b833acbc785e26`.
Ключ bridge создаётся в памяти и не выводится. Bridge закрывается в `finally`.

## Первый живой запуск

Node24, модель `gpt-5.6-luna`: запрос дошёл до bridge, но CLI завершился ошибкой.
Gateway получил HTTP502 `cli_failed`, время попытки — 89мс. Ответа модели нет;
этот прогон **FAIL**, не доказательство работающей генерации. Ошибка лимита
подписки не наблюдалась. Автоматические повторы и fallback отсутствуют.
Диагностика параметров CLI выполняется отдельно без вызова модели.

Вторая попытка после исправления пути runtime вернула 502 за 22мс:
`invalid_configuration`, exitCode1. Проверка полного набора аргументов
установила устаревший `tools.view_image=false`; строгая конфигурация отвергает
его. Alias удалён, поддерживаемое отключение `--disable view_image` сохранено.
Полный model-free preflight теперь проходит разбор конфигурации и завершается
только из-за пустого prompt, не начиная обращение к модели.

Root независимо выполнил **23 PASS**: 21 bridge regression и два теста
настоящего CLI, включая воспроизведение отказа устаревшего параметра.
Два найденных независимым ревью дефекта также закрыты: JSONL `null` больше не
роняет bridge; закрытие ждёт фактического завершения дочернего процесса.
