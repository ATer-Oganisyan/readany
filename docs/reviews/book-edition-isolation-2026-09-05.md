# Изоляция редакций: промежуточная проверка

## Проблема клиентского пути

Приватная backend-редакция может истечь, пока локальная книга и история
чтения остаются. Повторное разрешение этой же книги создаёт новую backend-
идентичность. Старые ответы не должны перезаписывать новую привязку.
Это не означает, что обычный импорт разных файлов использует один local book ID.

## Проверено на настоящем объекте сессии

Два новых теста сначала упали: после private 404 обновление прогресса снова
публиковало старый ready manifest; после stop() update() также публиковал его.
Исправление очищает latest при истечении и игнорирует update остановленной
сессии. Третий регресс проверяет отложенную загрузку медиа: после истечения
она не запускается заново, после новой успешной привязки работа возобновляется.
Локальный набор: 17/17 PASS. Независимое ревью первых двух регрессов: PASS.
Уже выполняющийся HTTP-запрос медиа этим изменением не отменяется.

## Принадлежность ответа manifest

Parser сохраняет wire edition/source SHA отдельно от хэша публикации,
проверяет их против запрошенной книги и прикрепляет копию идентичности запроса.
Она захватывается до await; для legacy-ответа без wire-полей используется
именно запрос, а не новая текущая привязка.

Перед публикацией клиент проверяет эту идентичность против текущей binding:
устаревший manifest не меняет язык, persisted store или transient status и
не запускает загрузку медиа. Проверяется также повторная публикация кэша
сессии при листании. Agent RED: same/edition/source — 1 PASS, 2 FAIL;
до исправления старый ответ записывал профили и язык в новое состояние.
После исправления root полный мобильный прогон: 175 suites / 1612 PASS,
TypeScript PASS. Покрыты valid wire, legacy, неверные wire-поля и cached replay.

Эта защита не охватывает отдельные callback identity/preview/error и
запросы greeting/send/memory. Их принадлежность ещё требует проверки.

## Перевыпуск того же исходника: store

Отдельный регресс воспроизвёл блокировку новой revision1 старой revision9.
При смене edition с одинаковым валидным source SHA store теперь сбрасывает
manifest и серверные assets/media, но сохраняет разговоры, память,
пользовательский голос и ручной портрет. Старые запросы сцен и anchor bindings
инвалидируются при смене edition даже без изменения markup identity.
Обычное обновление sourceUploaded и идентичная binding не сбрасывают профиль.

Полный локальный прогон после этих двух регрессов: 175 suites / 1614 PASS,
TypeScript PASS. Это проверка настоящих store actions, не native TTL-сценарий.
Стабильность characterKey между разметками остаётся условием продолжения
разговора: история не переносится по имени и не удаляется при исчезновении ключа.

## Полный контракт и оставшийся этап

Нужно разделять идентичность содержимого и транспортную backend-идентичность.
`manifest.contentHash` относится к публикации и не заменяет SHA исходной книги.

| Переход | Требуемое поведение |
| --- | --- |
| Тот же source SHA, новая private edition после TTL | Сохранить разговоры по стабильным characterKey; сбросить привязку профиля/revision/media; запретить старые async-записи |
| Другой SHA или неизвестная принадлежность | Архивировать прежнее состояние отдельно, не удалять и не подмешивать в новое |
| Новая публикация той же edition/SHA | Сохранить разговоры; сравнивать revision только в своей edition |
| Возврат к прежнему содержимому | Восстановить соответствующий архив, не переносить историю по совпадению имён |

Для разных исходников в store остаются открытыми A/revision9→B/revision1,
изоляция сохранённых профилей/истории и async greeting/send/memory после смены binding.
Нужны поведенческие тесты каждого перехода, включая удаление книги во время
запроса. Нельзя объявлять полную изоляцию достигнутой по тестам сессии.

Нативный прогон этих переходов, живой провайдер и нагрузочная приёмка
в этом этапе не выполнены. Подписочный тестовый транспорт не менялся.
