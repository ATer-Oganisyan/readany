# Персонаж: от экрана до запроса и сохранения ответа

Добавлены два mounted-теста actual NarraCharacterChatScreen на собственной
короткой истории про Анну и Льва. Не подменяются buildCharacterSystemPrompt,
completeNarraChat и parser ответа. Сетевой adapter возвращает контролируемый
ответ; UI-leaf и stores изолированы существующим harness.

Проверяются профиль, манера речи,25% прогресса, память о собеседнике, история,
последний вопрос и отрывок правильной книги в сериализованном запросе.
Проверяются purpose=character_chat, origin=user, analytics_tier=essential,
request_id и сохранение user/assistant в нужные book/character.
Пробелы вокруг ответа удаляются реальным parser. Побочные memory-запросы
не запускаются в этом коротком сценарии.

Вторая проверка исключает контекст чужой книги. Она не доказывает защиту от
спойлеров внутри текущей книги: future-marker присутствует только в чужом
отрывке. Это расширение покрытия, не исправление продуктового бага; первоначально
неверное ожидание теста не учитывало автоматически добавляемый request_id.

Агент:24/24 targeted PASS, TypeScript PASS. Использован Expo native-data-fetching.
Root перенёс только тест в изолированную RN0.86.3 установку через apply_patch:
полный mobile178 файлов /1661 PASS, TypeScript exit0. Рабочая старая установка
не обновлялась.
Следующий шаг для подписочного canary — провести этот фактический payload через
изолированный HTTP gateway, отдельно проверить точные provider bytes и ответ
живой модели. Текущие тесты не запускают подписку, не проверяют backend, качество
ответа модели, генерацию персонажа из книги или native UI. Длинная история
мобильного чата также не покрыта коротким сценарием.

## Воспроизводимый захват для следующего HTTP-прогона

`scripts/qa/capture-character-chat-fixture.mjs` запускает именно mounted-тест
с явным флагом захвата. Артефакт печатается только после проверок реального
запроса и сохранённого ответа. Удаляется только случайный request_id; остальные
клиентские поля, включая temperature, сохраняются. Процесс ограничен 20 секундами
и 1 MiB вывода, не наследует HOME, NODE_OPTIONS или ключи провайдеров.

Root независимо проверил 3/3 теста захвата: повторяемость, отказ при неверном
артефакте и ограничения дочернего процесса. Получено 6774 UTF-8 байта,
3 сообщения, SHA256 `79c29bdd6aa4aa52f5b3246ce55c753aa5cc7793b491a18c460457dc3943a039`.
Это хеш мобильного payload, **не разрешённый хеш provider request**: сервер
ещё добавляет свои инструкции и параметры. Живой вызов здесь не выполняется;
прежний подписочный canary и его allowlist не изменены.
