# Закладки: надёжность сохранения и текущая приёмка

Дата: 5 сентября 2026. Продолжение core-loop кампании после PR #77.
Состояние: локальное исправление, native acceptance и независимое review ещё идут.

## Подтверждённые дефекты

- Store публиковал добавление/удаление до успешной записи SQLite. Ошибка
  только логировалась; пользователь видел ложное подтверждение.
- Старый DB read мог стереть из UI только что сохранённую закладку.
- Удаление не ожидало незавершённого добавления.
- Reader сохранял текущий на момент ответа CFI вместо CFI нажатия.
- Не было корреляции ответа snippet, защиты от повторного tap и уборки таймера.

## Изменения

Store возвращает подтверждение commit, последовательно исполняет bookmark
writes, сохраняет прежнее состояние при отказе и не публикует книгу A в B.
Загрузка списка ожидает очередь и повторяет read при смене revision.
Bookmarks читаются после остальных аннотаций, чтобы их запоздалый read
не откатил список закладок.

Reader фиксирует book/CFI/chapter/id в момент действия; snippet получает
request ID и фактический CFI WebView. Чужой response игнорируется, текст
другой страницы не становится подписью. Через 500 ms сохраняется якорь
без необязательной подписи. Повторные taps во время сохранения не дублируют
действие. Выход сохраняет исходное намерение без позднего success-toast.
Успех и haptic следуют commit; ошибка доступна пользователю на RU/EN.

## Не принято

Полный native add→list→jump→delete→cold reopen, iOS и визуальная приёмка
desktop ещё требуют проверки. SQLite failure tests и desktop callbacks
проверены отдельно ниже; это не заменяет проверки на физических устройствах.

Параллельный Android UI QA обнаружил ранее возникший native crash, затем
ошибку sticky restart аудиосервиса. Причина не приписывается закладкам без
воспроизведения. Зелёный CI предыдущего коммита этого наблюдения не отменяет.

## Независимое review: desktop и атомарное удаление

Desktop toolbar продолжал подтверждать успех без ожидания нового Promise
store. Исполнение исходного обработчика показало: два клика до ответа БД
давали две вставки и два уведомления об успехе. Теперь toolbar и удаление
из TOC ожидают запись, блокируют повтор операции и показывают ошибку.
Пять поведенческих тестов исполняют реальные обработчики компонентов;
desktop TypeScript проходит.

Уточнение первоначальной гипотезы ревью: failed DELETE сам по себе не
удаляет закладку на другом устройстве. Действующий sync export исключает
tombstones, пока соответствующая живая запись существует. Подтверждённый
дефект другой: insertTombstone подавлял ошибку записи, и последующий DELETE
мог успешно удалить закладку без следа для синхронизации.

Удаление переведено на одну SQLite-команду через отдельную служебную таблицу
и AFTER INSERT trigger. Обязательная локальная инициализация схемы завершается
до команды; ошибка отклоняет запрос и допускает повтор. Триггер атомарно
записывает tombstone, удаляет закладку и служебную строку. Нет BEGIN/COMMIT
между awaited adapter calls и нет предположения о закреплении соединения
в Tauri pool. Служебная таблица не входит в явный SYNC_TABLES whitelist.
Прямое удаление при remote apply не запускает локальную команду и сохраняет
исходную временную метку. Повтор отсутствующего ID не продлевает tombstone;
локальное удаление учитывает уже увиденные будущие timestamps.

Восемь тестов на реальном SQLite проверяют успешную запись, принудительные
ABORT при DELETE и при tombstone INSERT, повтор, будущие timestamps,
remote direct delete, отказ DDL и независимые записи второго соединения.
Полный core после изменений: **84 suites / 675 PASS на Node 24 и Node 22.23.2**
(последний соответствует major-версии CI; SQLite выводит experimental warning).
Native SQLite и живая межустройственная синхронизация этим прогоном не приняты.

- Полный mobile после дополнительного TTS caller fix: **158 suites / 1 416 PASS**.
  App и desktop TypeScript прошли повторно.
- При TTS-аудите обнаружена неточность прежнего отчёта: исходный caller
  передавал React currentCfi вопреки комментарию. Отдельный actual-callback

- Независимый Android QA работает на fresh installation после отката AVD
  старым quickboot snapshot. Это не восстановление прежней библиотеки.
  Перед дальнейшими действиями сохранён полный clone AVD; другие приложения
  и исходные экспортированные DB/WAL не изменялись.
- Candidate native TrackPlayer patch проверен повторно: 9 Kotlin/JVM PASS;
  он не применён в установленной зависимости, поэтому не входит в native
  результат текущей читалки и ещё не готов к публикации с lockfile.

## Найденный UI-разрыв и новый список

Независимый Android-проход подтвердил: закладка добавлялась в SQLite, но
доступного списка для возврата с другой страницы не было. Это отдельный
дефект клиентского пути, не исправленный durable store сам по себе.

В меню книги добавлен пункт Bookmarks/Закладки. Он открывает существующий
native sheet с правильным заголовком, списком текущей книги, переходом по
сохранённому CFI и отдельным действием удаления. Загрузка имеет явные loading,
empty, error/Retry состояния; удаление не убирает строку до commit и
позволяет повтор после ошибки. Использованы существующие Typography/Icon,
deslop spacing и навигационный sheet; новая дизайн-система не подключалась.

Новая mounted-component регрессия: 7 PASS — exact CFI, book isolation,
deferred delete, failure/retry, запоздалый read предыдущей книги и завершение
удаления в книге A, пока в книге B ещё сохраняется другое удаление.
Подпись теперь берётся из exact visible context: 4 RED → 4 GREEN;
необязательная подпись остаётся пустой при отсутствии доказанного диапазона.
Независимое review дополнительно воспроизвело исчезновение индикатора
незавершённого удаления при commit другой закладки. Pending теперь
сбрасывается только при смене книги; отдельный тест RED → GREEN.
После всех дополнений основной агент повторил комплект: **26/26 PASS**
(panel, snippet, lifecycle, actual bridge round-trip).
App TypeScript и scoped Biome PASS. Reader MD5:
`522c0c08177b2126a77e0a64146f8f8c`.

Native list→jump→delete→reopen на iOS/Android пока ожидает отдельного
подтверждения UI QA. Предыдущее физическое удаление с текущей страницы
не засчитывается за этот отсутствовавший маршрут.

## Android: последующая независимая приёмка

На стабильном cold runtime успешно выполнено создание → две страницы →
холодный перезапуск → список → точный CFI-переход → удаление. Подпись
совпала с первым видимым текстом. После удаления SQLite: bookmarks=0,
tombstones 1→2, bookmark_delete_commands=0, служебная таблица существует.
Это подтверждает новую atomic реализацию на Android, но не живую синхронизацию
между устройствами и не iOS. Повторный cold reopen после удаления отдельно
не зафиксирован — не приписывать его этому gate.

Native QA нашёл два последующих UX-дефекта: Android formSheet не отображает
стандартный native toolbar, а пустой список указывал на отсутствующую кнопку
закладки в панели. Установленный ScreenStackFragment действительно не
добавляет appBarLayout для formSheet. Добавлен стандартный навигационный
Header через header option только для Android; iOS сохраняет native header.
Мобильная подсказка теперь описывает меню «Действия с книгой», desktop
подсказка не изменена. Header regression: 2 RED → 3 PASS с iOS control;
panel теперь 8 PASS. Повтор основного агента вместе с FBZ sync: 39 PASS,
mobile TypeScript PASS. Визуальная приёмка нового header ещё ожидается.

Последующий cold Android QA подтвердил заголовок Bookmarks, кнопку X,
возврат по X в Reader и исправленную mobile empty-подсказку. Доказательство:
`evidence/continuous-product-qa-2026-09-05/32-bookmarks-final-header.png`.
Отдельное accessibility review нашло жёстко заданное английское `Close`
в Android-компоненте; RU/DE platform-component регрессии воспроизвели ошибку,
локализация исправляется отдельным шагом. iOS этим результатом не принят.
