# Fixed-layout / CBZ — регрессии приёмки 5 сентября 2026

## Воспроизведено на Android

Исходная fixture: `12-river-comic.cbz`, четыре оригинальные PNG-страницы из
`/private/tmp/narra-audit-import-fixtures`. Импорт после исправления MIME прошёл,
но при открытии после `reader_loaded` экран оставался пустым более минуты.
Read-only CDP показал два iframe с `about:blank`, пустым document и нулевыми
размерами. Свидетельство исходного сбоя:
`evidence/android-2026-09-05/cbz-blank-before.png`.

## Причины и изменения

1. `iframe.load` → обработчик template → `applySettings` → повторный
   `setAttribute('spread', 'auto')` заново запускал `#applySpreadChange`.
   Renderer удалял только что загруженную страницу и повторял загрузку.
   `fixed-layout.js` теперь игнорирует неизменившиеся значения атрибутов.
2. Первое применение spread до `view.init()` уже начинало навигацию.
   `init.next()` затем переходил к следующему развороту одновременно с первым
   открытием. Начальная настройка теперь только строит развороты;
   первый переход остаётся за `init`/восстановлением позиции.
3. `openBook` template для любого fixed-layout выполнял `el.init({})`, игнорируя
   сохранённый CFI и процент. Теперь CBZ/PDF используют общий путь восстановления
   CFI, а при отсутствии/ошибке — сохранённую долю книги. Первое открытие без
   сохранённой позиции остаётся допустимым.
4. Переход оглавления на соседнюю страницу того же загруженного разворота менял
   изображение, но не `#side`, `index` и событие `relocate`. Теперь выбранная
   страница отражается в сохраняемом прогрессе без повторной загрузки изображений.

## Проверки и измеримый результат

| Сценарий | До → после в regression |
| --- | --- |
| Startup spread до init | Сам начинал load → **0 load**, пока не вызван начальный переход; открывается index 0 |
| Повтор settings из load handler | Уже за первый load получались **2** вызова загрузки той же страницы → **1**, iframe остаётся видимым |
| Повторное открытие CBZ/PDF | `init({})` вместо сохранённого CFI → точный CFI передан renderer |
| Отсутствующий/отклонённый CFI | Fallback не применялся → вызывается `goToFraction(0.5)` в обеих fixture |
| TOC внутри разворота | После выбора index 2 оставался **1**, relocate отсутствовал → **2**, одно relocate, без повторного section.load |

`fixed-layout-lifecycle.test.ts` исполняет **настоящий FixedLayout class** с
управляемыми DOM/iframe событиями; не ищет строки исправления в исходнике.
`reader-open-race.test.ts` исполняет настоящий `openBook` из template.
Каждая новая регрессия сначала упала на старом поведении: 2 startup/reload,
3 restore, 1 same-spread navigation. После исправления обе suites:
**9 PASS** (включая 3 прежних openBook race tests). App TypeScript — exit 0;
Biome на изменённых test files — 0 ошибок.

Reader asset пересобран с разрешения root: `reader.html` 600 KB (code 224 KB),
lazy PDF bundle 1654 KB. Последняя сборка этого этапа — около 00:44 локального
времени. До заявления о native успехе нужен full JS reload/new book open с этим
asset; наличие локального HTML само по себе не доказывает его загрузку устройством.

## Нативная приёмка после исправления

Android QA после reload подтвердил видимую первую PNG (`595×842`, loaded image),
а не только событие `loaded`. Свидетельство:
`evidence/android-2026-09-05/cbz-after-fix.png`. Физический swipe left перевёл
`river-01.png` (`/6/2`) в `river-02.png` (`/6/4`). Таким образом, blank loop
воспроизведён до и устранён на фактическом устройстве после исправления.

**Отдельный дефект, выявленный после blank fix:** три right taps на первой странице её не меняли;
после swipe на вторую right tap `(890,1050)` вернул первую. Это ошибочное
направление hit-test в масштабированном iframe, а не новое зависание загрузки.
Исправление координат выполнено reader_fixes и отдельно проверено Android QA:
3 next, prev, center-controls, выбор второй страницы в TOC, Back/reopen точно
`/6/4`. iOS подтвердил изображения 1→4→3 и повторное открытие на третьей странице.
Актуальные свидетельства — в [Android](android-native-qa-2026-09-05.md) и
[iOS](ios-native-qa-2026-09-05.md) отчётах; успех не приписывается одному blank fix.

Подтверждение ограничено перечисленными fixture/сценариями. Остаётся отдельно:

- single/double layout не запускает непрерывную перезагрузку;
- широкая матрица fixed-layout EPUB, размеров экранов и направлений письма.

PDF readability/selection потребовали последующих исправлений и приняты отдельно
в [PDF report](pdf-text-layer-2026-09-05.md). Соседние EPUB/TXT входят в native
форматные прогоны, но новый EPUB Range loader ещё ожидает installed AFTER.

Процент ускорения не заявляется: есть исходное наблюдение «пусто более минуты»,
функциональные regression и видимая страница после, но нет сопоставимого замера
времени cold-open до/после.
