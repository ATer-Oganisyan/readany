# Замена редакции без переоткрытия приложения

Новый сценарий воспроизвёл проблему шире отдельного позднего ответа: уже показанный preview оставался после смены binding, а общая сессия продолжала опрашивать прежнюю редакцию. Новая проверка упала на сохранённом старом preview.

Теперь retained-сессия наблюдает смену edition/SHA: останавливает старую сессию с её AbortController и таймерами, очищает временный статус и запускает новую для текущей книги. Подписка снимается с последним потребителем. Синхронные записи binding из самого bindBook не перезапускают его: это важно для преобразования FBZ в FB2 и завершения source upload.

Проверки: сценарий старый preview → внешняя смена binding → немедленная очистка → запрос новой редакции → готовые персонажи PASS. После последнего release смена на третью редакцию не запускает запросы. Старый cache-тест удерживает ответ новой редакции незавершённым, чтобы проверять именно отсутствие повторной публикации старого кэша. Регрессии FBZ сохранены. Полный прогон до дополнительной проверки release: 177 файлов / 1655 PASS; TypeScript PASS.

Границы: это реакция на изменение Narra binding, не отдельный observer удаления книги из библиотеки или изменения файла без обновления binding. Такой жизненный цикл ещё не принят целиком. Native-прогон не выполнен: Android emulator-5554 подключён к Metro8081, отдельного LOCAL-клиента/пробросов8082/18787 нет; TEST не меняли. iOS XCTest/AX после прежнего системного падения не запускался. Применён Expo native-data-fetching: отмена старой сессии вместе с проверкой идентичности ответов.
