# Озвучка: поздний запуск после отмены

## Воспроизведено

Независимое review исполнило реальные callbacks useReaderTTS с управляемыми
ответами WebView. Три исходных сценария упали до исправления:

- Старт страницы → ожидание текста → Stop → поздний ответ запускает play.
- Старт страницы → новый старт выделения → старый ответ перебивает выделение.
- Stop во время ожидания следующей главы → старый prefetch запускает страницу.

Внутренняя generation аудиоплеера не закрывала эту гонку: поздний вызов play
после Stop создавал уже новую player session.

## Исправление и проверка

Добавлен счётчик намерений на уровне reader preparation. Новое действие,
локальный Stop/Pause, смена книги и unmount инвалидируют старую подготовку.
Проверки после awaited text/context/chapter extraction и перед deferred play
не дают старому результату перехватить актуальную озвучку. Context cache
разделён по bookId. Явный CFI seek остаётся явным seek; обычный старт страницы
использует актуальный видимый контекст WebView, без stale React CFI.

Покрыты также остановка во время 320 ms CFI-перехода, реальные cleanup/reset
effects, latest-wins и успешный старт без отмены. Автор: 9 targeted PASS,
полный mobile **162 suites / 1 447 PASS**, TypeScript/Biome PASS.
Основной агент независимо повторил TTS, header, bookmarks и FBZ комплект:
**5 suites / 48 PASS**. Core: **84 suites / 675 PASS**.

## Не закрыто этим исправлением

- До запуска плеера подготовка текста не имеет отдельного видимого статуса:
  пользователь не получает доступную кнопку Stop именно на этом этапе.
  Прямой вызов обработчика в тесте не доказывает доступность отмены в UI.
- Внешний Stop глобального mini-player не вызывает локальный reader handler;
  нужен явный cancellation epoch на общем уровне, отдельно от естественного
  завершения воспроизведения. Исправление проектируется отдельно.
- Нативное воспроизведение, фактическое отсутствие позднего звука и непрерывное
  чтение через главы должны пройти независимый Android/iOS прогон.
- Candidate TrackPlayer recovery patch решает другой дефект, не установлен
  и не считается частью этого JS-результата.

Тесты не подтверждают ни качество голоса, ни готовность всей озвучки к релизу.

## Следующий batch: общая отмена и доступная подготовка

External Stop воспроизведён отдельным RED: общий store.stop теперь увеличивает
explicitStopEpoch, reader подписан именно на него, не на natural stopped.
Начало подготовки сразу показывает статус; повторный toolbar tap отменяет её.
Пустой текст и ошибка имеют отдельные сообщения. Android/iOS toolbar в состоянии
preparing использует доступную кнопку отмены, а не disabled audio-loading spinner.
Изменения используют существующие native controls/типографику и Expo UI skill;
новой дизайн-системы или нативных API для статуса не добавлено.

Воспроизведена ещё одна гонка: старый EOF запускал продолжение во время нового
page/CFI preparation. Старый onEnd снимается и не восстанавливается промежуточным
рендером; обычное непрерывное чтение отдельно проверено. Полный mobile после
batch: **165 suites / 1 466 PASS**, TypeScript PASS; основной агент повторил
озвучку, toolbar/status и FBZ: **53 PASS**. Core повторно **675 PASS**.

Прежние пункты о недоступной локальной подготовке и external Stop выше описывают
состояние до этого batch, а не текущую реализацию. Новые UI/voice пути ещё
не прошли независимый native Start→Cancel/Stop; старое наблюдение stopped без
подтверждённого запуска не засчитывается как успешная отмена.

## Приёмка новой APK и доступность Cancel

Android QA на APK `2f771113…` подтвердил сохранность книги/точного CFI и
настоящий переход в loading: 86 chunks, первый текст «пристани и рассказал…»
соответствует видимой странице. Gateway вернул 501/502; остановка после
retries не засчитывается как успешный Stop или доказательство отсутствия
позднего звука. В свежем crash buffer падений не было, но это короткий проход,
не primary-crash soak.

Root воспроизвёл отдельный UI-дефект: setShowControls(true) во время первых
трёх секунд не отменял introductory timer; подготовка теряла кнопку отмены.
Сеттер теперь отменяет таймер, а автоматический intro-reset остаётся внутренним.
Regression RED → GREEN. Добавлена отдельная текстовая Cancel в статусе
подготовки/загрузки аудио: она не зависит от disabled native loading spinner.
Dock расширяется по содержимому, поэтому кнопка находится внутри реальных
touch bounds, а не визуально за границей родителя. Controls/status: **10 PASS**,
mobile TypeScript PASS. Новый native Cancel gate ещё идёт.

Независимое review дополнительно воспроизвело Pause/sleep-timer cancellation
gap (четыре RED): естественное завершение уже перевело player в stopped,
а pending continuation после глобальной Pause мог вызвать новый play.
Это отдельное исправление общей отмены, не изменение смысла Pause на Stop;
регрессии Resume и natural continuation обязательны.

Pause/sleep batch завершён: общий `explicitCancellationEpoch` увеличивается
при Stop/Pause, включая Pause во время stopped/pending continuation.
Очередь и позиция при Pause сохраняются; Resume не пересинтезирует текст.
Natural EOF epoch не меняет. Четыре RED исправлены, соответствующие два suites
дали 35 PASS. Root повторил канонический mobile `pnpm test`:
**165 suites / 1 475 PASS**, core **675 PASS**, отдельная Node audio-policy
suite **2 PASS**; новая APK не содержит bundled audio. Прямой запуск Vitest
без путей ошибочно подобрал Node-test `.mjs` из scripts (0 Vitest tests);
это не выдаётся за зелёный прогон — указанные PASS относятся к правильным runners.

Следующий cold-native Cancel gate остановился на белом экране до новых JS-логов.
QA сохраняет evidence и диагностирует bundle/inspector; runtime меняется только
после установления причины. Это отдельная проблема запуска, не доказательство
успешной отмены и не подтверждённое новое нативное падение.

Последующая проверка того же PID9914 без повторного restart: Library прошла,
собственная книга открылась на точном прежнем CFI с asset522c. Белая фаза
завершилась сама; постоянный freeze не воспроизведён. Длительный dev startup
остаётся наблюдением, не измерением скорости release. Cancel gate продолжен.
