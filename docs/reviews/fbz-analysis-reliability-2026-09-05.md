# FBZ: от чтения к персонажам и другим AI-функциям

## Клиентский дефект

Независимый Android UI QA импортировал собственную FBZ-книгу и смог её читать,
но переход к персонажам показывал неподдерживаемый формат. Это разрыв
основного пути: упаковка FB2 в ZIP не должна требовать от клиента искать книгу
повторно в другом формате.

## Локальное исправление

Перед backend binding клиент извлекает проверенный FB2 из FBZ/FB2.ZIP.
Проверяются структура XML, CRC архива и лимит распакованного файла 50 МиБ.
На сервер отправляются точные XML-байты с FB2 MIME, а не ZIP под чужим типом.
SHA256 и edition относятся к этим же байтам. Кодировка Windows-1251 сохраняется.

Локальная читаемая книга остаётся архивом: format, filePath и contentHash
не подменяются идентичностью производного FB2. Производный источник хранит
ссылку на исходный путь и хеш; после смены архива старый binding не используется.
Совпадение производного FB2 с каталогом тоже не переписывает идентичность архива.

## Доказательства и границы

Автор исправления выполнил полный mobile: **160 suites / 1 431 PASS**,
mobile TypeScript и scoped Biome. Серверные parser/API тесты: **36 PASS,
без пропусков**. Это результаты до последующего дополнительного теста панели
закладок и до исправления cache recovery, а не финальная метрика всей кампании.

Регрессии проходят реальную цепочку ZIP → XML bytes → file SHA256 → register
→ PUT с контролируемым транспортом. Покрыты повреждённый архив, CP1251,
повторный импорт, валидный производный cache и лимит размера.

Независимое backend-review обнаружило дополнительный recovery gap: если
производный FB2 потерян, а запись о нём сохранилась, повтор не восстанавливает
его из целого исходного архива. Исправлено: missing/empty cache восстанавливается
из оригинального архива; хеширование и upload используют один снимок источника.
Две новые поведенческие регрессии: RED → GREEN. Основной агент повторил
весь backend-book-sync: **28 PASS** в комплекте с header/panel **39 PASS**;
mobile TypeScript PASS. Native-приёмка FBZ не завершена. Живые AI-результаты при TEST HTTP 502
не подтверждены. Долговременная уборка неиспользуемых производных файлов
требует отдельного безопасного lifecycle с учётом активных загрузок.
