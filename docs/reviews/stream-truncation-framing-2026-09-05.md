# Потоковый ответ: обрыв и границы SSE-событий

## Найдено и исправлено

Streaming route, как прежний complete, принимал явный finish_reason:length
за успешный ответ. Кроме того, raw-передача сетевых chunks позволяла отправить
клиенту половину JSON: после ошибки следующего chunk событие error приклеивалось
к незаконченному data. Root воспроизвёл это настоящим HTTP-тестом:
`data: {"choices":[{"finish_reaevent: error...` вместо самостоятельного error.

Collector теперь отклоняет length во время чтения. Новый relay передаёт только
целые проверенные SSE-события. Не буферизуется весь ответ: валидные события
отправляются сразу; незавершённое событие ограничено512KiB. Сохраняются точные
байты UTF-8 и CRLF. При ошибке relay больше не принимает продолжение.

После partial output HTTP-статус уже200, поэтому клиент получает отдельное
`event:error` с PARSE. Запись length и следующий DONE не передаются, попытка
завершается failed. Старое предупреждение после успешного завершения удалено.

## Проверки

- Collector:3 RED→GREEN. Relay:5 начальных поведенческих RED→GREEN,
  дополнительные проверки границ/закрытия/переносов строк.
- Root actual HTTP RED→GREEN: валидный первый текст, следующий JSON разделён
  сетевой задержкой; после исправления ровно2 корректных события — текст и error.
  Нет DONE, ровно1 upstream-вызов, слот освобождён; явный повтор получает полный
  поток с DONE. Non-stream сценарий тоже сохранён.
- Проверены разбиение каждого UTF-8/CRLF байта, coalesced-события,20 событий
  сверх суммарного per-frame лимита, переполнение и недописанное событие на EOF.
- Root полный core:85 файлов/677 PASS. Два новых теста реального StreamingChat
  проверяют token→error-event и token→iterator-error: onComplete не вызывается,
  автоповтора нет, явный новый stream работает. Agent iterator подменён;
  это не полный LangChain→hook→БД путь. Runtime клиента не изменялся.
- TypeScript приложения exit0. Нативный диалог и новый live-вызов не выполнялись.
- Финальный независимый серверный прогон root:28/28 PASS (collector, relay,
  complete/stream HTTP, очередь/отмена и конкуренция живого/фонового чата).

## Оставшиеся ограничения

Не принимаются как решённые: скрытое усечение без finish_reason; ранний DONE
до последующего мусора; backpressure; полный клиентский путь отображения ошибки
после реально показанного текста через LangChain, hook и БД.
Строгий relay теперь отклоняет недописанное событие без завершающей пустой строки
на EOF; такие потоки не считаются нормальным завершением.
Релизная нагрузка и длительные прогоны ещё не выполнены.

Использован Expo native-data-fetching; изменения пока не задеплоены.
