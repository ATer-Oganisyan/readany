# Проверка голоса на записанном живом ответе

В сохранённом ответе короткого живого прогона модель одновременно указала `gender=female` и несовместимый голос `She`. Выполнен отдельный replay через текущий `createInternalGenerationService`: использованы неизменные ответы synthesis/recall/audit из committed evidence и evidence IDs/нормализованные позиции из проверенного исходного step-2 request. Тест не запускает модель, PostgreSQL, HTTP или медиа.

Результат: нормализованный профиль содержит `female`, голос `Che`, единственную черту `честность`, пустые примеры речи и неизвестный стиль речи. Повторный вызов возвращает идентичный кэш без дополнительных model calls. Защита уже работала; изменение production-кода не потребовалось.

Проверки: Node24, `node --test services/narra-gateway/test/recorded-window-profile.test.mjs services/narra-gateway/test/voices.test.mjs services/narra-gateway/test/internal-generation-service.test.mjs` — 45 PASS, 0 FAIL, 0 SKIP. Первоначальная ошибка нового теста была неправильным полем `bookLanguage` в запросе теста; после его удаления контракт соблюдён. Это не RED→GREEN исправление production-дефекта.

Границы: доказан результат сервиса синтеза и его кэш, не конечная публикация прежнего живого прогона, не реальное звучание, не выбор TTS-провайдера в мобильном приложении. Следующая приёмка должна проверить опубликованный профиль и воспроизведение на клиенте.
