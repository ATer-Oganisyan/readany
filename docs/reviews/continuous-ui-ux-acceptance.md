# Непрерывная клиентская приёмка NARRA

## Задача

Проверять не наличие компонентов и зелёные unit-тесты, а возможность клиента
пройти путь «своя книга → чтение → контекстные функции → продолжение → возврат»
без потери данных, ложных подтверждений и блокировки чтения AI-обработкой.
Этот документ задаёт критерии, а не объявляет их достигнутыми.

## Цикл команды

1. Независимый UI/UX-агент проходит приложение физическими нажатиями на
   эмуляторе/симуляторе, используя собственные тестовые книги.
2. Для дефекта фиксирует шаги, ожидаемый и фактический результат, платформу,
   версию кода/reader asset, скриншот и релевантный лог без секретов.
3. Отдельное frontend/backend-ревью определяет причину и затронутый контракт.
4. Исправление получает поведенческий тест: сначала воспроизведение ошибки,
   затем успешный результат. Проверки строк исходника этого не заменяют.
5. UI/UX-агент повторяет исходный маршрут и соседние сценарии на стабильной
   версии приложения. Во время native-прохода не менять runtime-код/Metro.
6. Результат вносится в журнал: PASS, FAIL или NOT TESTED с причиной.
   После исправления приоритетного дефекта цикл продолжается со следующего пути.

Работа повторяется во время активной QA-кампании. Это не обещание автономного
наблюдения после завершения сессии: для него нужен отдельный работающий runner.

## Основные сценарии

| Путь клиента | Обязательные проверки |
| --- | --- |
| Импорт → библиотека → первая страница | Файл и ссылка; все заявленные форматы; EPUB, FB2, FBZ/FB2.ZIP, TXT, PDF отдельно; кириллица/кодировки, большая книга, без обложки, битый/пустой файл, неверное расширение, дубликат, повторный импорт, отмена и отказ сети. Нет карточки успешного импорта до сохранения; прежняя книга не повреждена. |
| Чтение → уход → возврат | Быстрое листание в обе стороны, главы, смена оформления, фон/возврат, холодный запуск. Текст не застревает под вечным loading; сохраняется точное место. |
| Закладка → другая страница → список → переход → удаление | Подпись соответствует видимой странице; переход ведёт к сохранённому якорю; повторный tap не дублирует; ошибка БД не выглядит успехом; удаление сохраняется после перезапуска. |
| Чтение → персонажи → профиль → диалог → чтение | Разметка не блокирует чтение; понятны очередь/прогресс/ошибка/повтор; персонажи и биографии относятся к текущей книге и прочитанному контексту; переписки не смешиваются между книгами и персонажами. |
| Чтение → озвучка → пауза/перемотка → продолжение | Старт с видимого текста, не старого React-состояния; один активный источник аудио; ясны buffering/playing/error; фон, смена страницы и возврат не запускают неожиданную старую фразу. |
| Narra / общий книжный чат → чтение | Контекст текущей книги и позиции; отмена, ошибка сети, повтор, streaming и сохранение переписки; нет дублирования сообщений или ответа в другой книге. |
| Чтение → сцена → ожидание/ошибка → чтение | Можно читать во время генерации; дедлайн ограничивает зависший запрос; terminal error видима и не запускает скрытый бесконечный повтор; готовая сцена соответствует выбранному контексту. |

Каждый основной путь повторяется как минимум на Android и iOS. Offline,
медленная сеть, отказ backend и холодный запуск — отдельные режимы, а не
замена успешному online-прохождению. Mock/model-free тест не подтверждает
качество живых персонажей, диалогов, сцен или звука.

## Выпускной gate

- Нет открытых воспроизводимых падений, зависаний, потери данных и ошибок
  идентичности книги/персонажа в обязательной матрице.
- Все обязательные пути прошли на выпускном кандидате без HMR; проверка
  dev-client сама по себе не является приёмкой release-сборки.
- У каждого исправленного дефекта есть регрессия и независимый повтор.
- Реальные AI/TTS-провайдеры проверены отдельно, включая отказ и восстановление.
- Производительность измерена на обозначенных устройствах: импорт→первый текст,
  листание p50/p95, восстановление места, первый полезный AI-результат, старт
  аудио. До/после сравниваются только при одинаковых книгах и условиях.
- Нагрузка на тысячи клиентов проверена отдельным профилем backend и очередей;
  один эмулятор и число unit-тестов не доказывают масштабируемость.

«Без известных дефектов в пройденной матрице» — проверяемый результат.
Абсолютное отсутствие любых багов и оценка 10/10 без этих доказательств
не используются как статус готовности.
