# Выбор книг и пакетное удаление: клиентская приёмка

## Воспроизведение

На Android LOCAL `95d230c` удержание карточки показывало только Remove/Cancel.
Другого входа в режим выбора не было. `LibraryScreen` передавал в `BookCard`
обработчик и состояние выбора, но карточка их игнорировала. Тесты отдельного
batch-delete hook не покрывали достижимость действия с экрана.

## Исправления

- `2fdf09d`: пункт Select в существующем native-меню; выбор первой книги,
  переключение остальных, checkbox-состояние для accessibility. В режиме
  выбора меню/Android overlay не перехватывает нажатия; Reader не открывается.
  Cancel возвращает обычное открытие и меню удаления.
- `95a8e05`: отметка перенесена в правый нижний угол. Первый native-скрин
  выявил перекрытие начала названий верхним левым badge. На итоговом native
  снимке названия и прогресс не перекрыты, выбранная/невыбранная отметки видны.

Использованы существующие CheckIcon, тема и радиусы; новая дизайн-система
не добавлялась. Expo building-native-ui применён к нативным состояниям и меню.

## Доказательства

- Две исходные mounted-регрессии падали до подключения selection; после
  исправления 4 теста PASS, включая iOS adapter с замоканными SwiftUI leaf.
  Это не запуск iOS Simulator.
- На точном Android JS-снимке `2fdf09d`: 180 файлов / 1718 мобильных тестов,
  TypeScript PASS. Отдельная геометрическая регрессия: RED → GREEN, всего
  5 selection-тестов PASS на `95a8e05`.
- Native `2fdf09d`: Select → 1 selected → выбрать PDF → 2 → снять → 1 →
  Cancel → Library. Далее выбраны четыре собственные тестовые карточки,
  подтверждение удаления показало 4, результат: Deleted 4 / Not deleted 0.
- Сразу после удаления, **до открытия Reader**, read-only persisted library
  содержит ровно две защищённые книги. Root независимо сравнил их ID,
  полные CFI и дробные progress с baseline: точное равенство. Четыре disposable
  ID отсутствуют. Файлы исходных QA-книг на хосте сохранены для повторного импорта.

## Что ещё не принято

Повторный импорт после hash-fix принят на Android `2fdf09d`: одна own02,
Added 0 / updated 1, точные ID/CFI/progress/hash и путь сохранены, Reader
открыл прежнюю страницу. Защищённые own01/27 тоже открыты для чтения.
Отказ удаления с реальной
ошибкой диска не инъецировался: отказ покрыт mounted-тестами и настоящей
SQLite на хосте. Свежий iOS, TalkBack/VoiceOver и все bulk-действия, кроме
описанного happy path удаления, не приняты. Панель bulk-действий нуждается
в отдельной проверке доступных названий кнопок.

Следующий read-only review выявил дополнительные кандидаты на регрессии:
завершение старого удаления может перезаписать новый выбор после Cancel;
Select all сравнивает количества вместо ID при смене фильтра; состояния
batch-тегов и перемещения требуют проверки сохранения и обратной связи.
Эти сценарии не включены в принятую выше последовательность.
