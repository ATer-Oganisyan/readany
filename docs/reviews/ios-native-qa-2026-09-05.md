## Среда и сборка

- Установленные пакеты приведены к существующему lockfile через frozen install.
  `@expo/dom-webview` обновлён с фактически устаревшего 55.0.6 до объявленного
  57.0.1. Проектные версии не подбирались наугад.
- Выполнен осознанный `pod install`; Podfile.lock и Pods/Manifest.lock совпадают.
  Полная локальная native сборка завершилась `BUILD SUCCEEDED`, канонический
  dev-client установлен. Настоящий cold start → Library → My books прошёл.
- Wrapper проверяет фактически установленные зависимости до запуска/сборки.
  Скрипты тестов и генерируемые Android build-папки больше не вызывают ложную
  необходимость пересобирать iOS. Поведенческие проверки guard/fingerprint есть.
- Simulator использует единственный выбранный Xcode, localhost Metro, без
  туннелей. Pasteboard sync выключен. Fast Refresh временно выключался для
  воспроизводимой проверки; в конце включён через native DevSettings,
  `RCTDevMenu.hotLoadingEnabled=true` подтверждён в сохранённых preferences.

На момент первого пакета библиотека содержала одну существующую книгу и шесть
audit-книг. Повторное добавление CP1251 оставило семь записей и прежние 54%
до открытия. Затем reader после загрузки откатился к более раннему тексту;
это отдельный renderer/resume дефект, а не сброс импортом.

Набор 07 не был выбран в одном из ранних проходов Files; позднее действительно
выбран, импортирован и прочитан в общей матрице. UI-driver
может найти accessibility-элемент под нижними вкладками, но нажать вкладку:
перед выбором нижних строк теперь выполняется прокрутка до полной видимости.
Снимок загрузчика или найденное имя книги не считается успешным открытием.

## Метрики и ограничения

Публикуются наблюдаемые исходы, число реально выбранных/сохранённых файлов,
пройденные переходы и точные адреса текста. Сопоставимого исходного замера
скорости iOS нет, поэтому процент ускорения не рассчитывается.
После каждого исправления обязательны повторный native сценарий и общий прогон.
Debug-клиент, Simulator и локальные тесты не доказывают производительность
физического устройства, готовность App Store архива или ёмкость production.

Уточнение учёта повторного импорта: существующие совпадения не означают
`skippedDuplicates`. Store обновляет те же записи и возвращал их в `imported`.
После повторного выбора всех 25 файлов библиотека осталась 17→17, но старый
UI показал Imported 17 / skipped 0 / failed 8. Это был дефект формулировки/счётчика,
не размножение карточек. После отдельного `refreshedCount` итоговый native повтор
прошёл: Added 0 / updated 17 / skipped 0 / failed 8, Library 17→17. В прогоне
Maestro `2026-09-05_112246` Details открылся с первого стабильного semantic tap;
координатный fallback не исполнялся. Новый Sonner patch сохраняет прежние
изменения и исправляет resume таймера после короткого горизонтального жеста;
18 actual source/ESM/CJS gesture tests проходят, отдельный native short-swipe
autodismiss ещё не принят.

Fresh archives: `.maestro/ios-fresh-archive-import.yaml`, успешный прогон
`2026-09-05_112536`; первоначальный запуск без launchApp стартовал с домашнего
экрана и не считается приложенческим дефектом или пройденным тестом.
Старые 08/09 записи и их позиции сохранены. После двух новых архивов исходная
книга сохраняет `epubcfi(/6/6!/4/2/2,/10,/12/1:34)`.

При последующем открытии исходной книги Foliate нормализовал адрес видимого
диапазона до `epubcfi(/6/6!/4/2/2,/8/1:180,/12/11:147)`. Прежний начальный
якорь `/10` находится внутри этого диапазона (проверено production CFI
compare/collapse), и его абзац виден на снимке. Это не побайтово равный CFI
до открытия и не доказанная потеря позиции. Цепочка профиля/чата возвращает
уже нормализованный CFI без изменения.

Эта же исходная книга выявила отдельный дефект контекста: подсветка имён
меняла живой DOM Range, и в контекст попадало начало невидимого абзаца вместо
конца страницы. Снимок и сохранённый context дали native RED; общий reader
asset теперь восстанавливает Range по неизменному CFI с проверкой обратного
адреса. Итоговый iOS проход `2026-09-05_115826` подтвердил исправление на
исходной книге: прежний CFI, начало «напитку непривычного», конец «Он был
хмелен, но говорил» совпадают у реального видимого экрана и сохранённого
контекста после открытия Characters. Невидимое начало больше не попадает
в контекст, видимый конец не теряется. HTML SHA256:
`6baef5c2326905775f65cb7ecc2895dead889ca42ddf70a0ceebf977d1f44a24`.

Промежуточная правка типизации `BookImportError.cause` прошла TypeScript, но
вызвала настоящий cold-start RED в Metro: class `declare` не поддерживался
текущим Babel pipeline. Поле перенесено в type-only interface merging;
добавлены два регрессионных теста реального Babel config для iOS/Android,
которые упали до исправления. После исправления cold start и чтение выше
снова прошли. Этот промежуточный сбой не скрывается за общим числом тестов.
