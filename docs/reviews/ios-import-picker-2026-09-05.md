# iOS: выбор CBZ при восстановлении файла книги

## Подтверждённое поведение

На iOS 26.5 одиночный Files picker с прежним MIME-списком показывал собственный
QA CBZ, но нажатия по имени и физический double-tap не завершали выбор. В том же
окне PDF сразу выбирался и доходил до штатного предупреждения о несовпадении
книги. Это отличает проблему выбора файла от ошибки импорта/восстановления.
BEFORE включает три физических попытки CBZ и успешный контроль PDF. Причина
в несовместимости MIME/UTI-фильтра с этим файлом/provider — вывод по A/B, а не
утверждение о документированном дефекте UIKit.

После cold reload root проверил действующий JS helper (`ios → ["*/*"]`) и
физически выбрал CBZ. На снимке после действия отображалась правильная
`river-03.png`, страница 3/4. По проверке root восстановление сохранило ID книги,
CFI и hash, создало новый copy-on-write путь; файл по новому пути существует.
Счётчик Library остался 20 → 20; CFI остался `epubcfi(/6/6)`; SHA исходника
совпадает с безопасной резервной копией. Исходная запись книги сохранилась.
Автоматический сценарий завершился ошибкой `kAXErrorServerNotFound` при поздней
проверке Reader accessibility, а не при выборе/восстановлении файла. Успех
подтверждён изображением и состоянием хранения, не одним exit code драйвера.

## Ограниченное изменение

`bookImportPickerTypes` использует `*/*` только на iOS; локальный исходник
`expo-document-picker` переводит это в `UTType.item`. Android сохраняет прежний
MIME-список, включая aliases CBZ/ZIP. Дополнительные форматы не объявлены
поддерживаемыми.

Все три клиента используют общий helper:

- библиотечный импорт: прежний `multiple: true`;
- восстановление через `openMobileBook`, включая повтор picker: `multiple: false`;
- восстановление в уже открытом Reader: `multiple: false`.

Вариант множественного выбора для восстановления не потребовался и не принят.

## Независимый review и проверки

Обхода admission не найден. Импорт и фактическое восстановление вызывают
`bookImportFormat` и `validateMobileImportFile` до создания постоянного файла и
записи книги; новая попытка восстановления сохраняет copy-on-write семантику.
Неподдерживаемое расширение не превращается в книгу из-за широкого iOS picker.
Подтверждение несовпадающей книги по-прежнему требуется, отмена не пишет данные.

Новый `reader-missing-book-picker.test.ts` исполняет настоящий AST callback
Reader, его helpers сравнения книги и реальные format/picker helpers. Семь
проверок: iOS policy + ожидание ACK, неизменный Android список, cancel,
declined mismatch, unsupported selection, failed restore и provider error.
Нативная граница picker и DB порты изолированы; эти тесты не подменяют native
проверку того, что Files действительно завершает выбор CBZ.

Независимый прогон официальным Node 24: **6 suites / 119 PASS**, app TypeScript
PASS, Biome нового теста PASS, `git diff --check` PASS. Набор включает реальные
store import regressions, source validation, mounted import actions и
`openMobileBook` вместе с новым Reader callback.

## Границы

Это исправление пути выбора, не полная гарантия декодирования любого CBZ/PDF.
Admission проверяет контейнер и структуру, а не каждое изображение/страницу
полным декодером. Проверка других сторонних iOS file providers не проводилась.
Пользовательские исходники и прежние записи не переписывались reviewer-ом;
root проверял восстановление собственного QA файла с безопасной резервной копией.
