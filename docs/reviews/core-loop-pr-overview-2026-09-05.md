## Основное

Стабилизация core loop **импорт → чтение → контекстное взаимодействие →
возврат к сохранённому месту** в `mishanaer/Narra`.

- **Импорт:** проверка настоящего содержимого, надёжное сохранение, безопасный
  повтор/новая редакция/repair; FB2/TXT кодировки, архивы, URL timeout/Cancel,
  честные результаты смешанной загрузки. Собственные форматы открыты на iOS/Android.
  После одиночного импорта доступно «Открыть» именно сохранённую книгу;
  свежий FBZ по ссылке → Open → Reader принят на обоих эмуляторах.
- **Чтение:** зависания и пропуск глав, WebView request races, EPUB Range,
  PDF/CBZ rendering/позиции, checkpoint, book-scoped заметки и возврат без
  накопления Reader; управление, тема, контраст и лишние фоновые renders.
  Явно выбранная видимость управления теперь сохраняется после оглавления;
  загрузка временно показывает выход, не стирая выбор. Native RED→GREEN на iOS.
- **Персонажи и чат:** ошибки анализа не скрываются как пустой успех,
  русские identity/kinship проверки, восстановление UI, точный контекст
  страницы в character prompt, ограничение полного complete-response.
  Повторные события отправки одного render больше не дублируют запрос;
  защита освобождается при сетевой и локальной ошибке (mounted RED→GREEN).
  Manifest проверяется по редакции и SHA исходника до обновления профилей,
  языка и статусов; запоздалый ответ и повторная публикация старого кэша
  отклоняются. Остановленная/истёкшая сессия не публикует старый анализ.
  Перевыпуск той же книги принимает новую revision1 после старой revision9,
  сохраняя разговор, память и ручные настройки; старые серверные медиа сбрасываются.
  При изменении валидного SHA прежнее AI-состояние хранится отдельно;
  возврат к исходнику восстанавливает его историю без подмешивания другой версии.
  Незавершённые ответ/приветствие/placeholder/память отменяются при смене
  идентичности книги; возврат A→B→A не разрешает запись старого результата.
  Исправлена потеря родства при публикации: уже восстановленные resolver
  участники теперь сохраняются, без ссылок на исключённых персонажей.
  Живой multi-chunk прогон выявил потерю примера речи: normalizer теперь
  восстанавливает до трёх собственных точных реплик, если модель их пропустила,
  без дополнительных AI-вызовов. Записанные ответы прошли полный PG replay.
- **TTS:** старт с видимого остатка предложения; поведенческие регрессии
  и проверка реального Android DOM без сдвига позиции. Отмена незавершённой
  подготовки, включая общий Stop, видимый Preparing/Cancel и защита от старого EOF.
  Для отдельного экрана сцены Stop теперь доступен при подготовке; отмена
  проходит до сети/сохранения, старый ответ не перезаписывает новый запуск.
  Ошибочный MP3 и oversized body не запускают повторную платную генерацию.
  Сценарий и его кэш проверяются на полное сохранение исходного текста;
  выдумки/пропуски/перестановки не доходят до синтеза. Ошибка видима на экране.
- **Закладки:** подтверждение только после БД, точный якорь и подпись,
  список/переход/удаление, Android header/Close; atomic tombstone+DELETE.
- **FBZ → AI:** проверенный XML извлекается без подмены идентичности архива;
  cache восстанавливается при потере, повторный импорт не использует старый binding.
- **Сцены/backend:** terminal failure отделён от явного retry, bounded inline
  polling/download, SQL idempotency/quota; admission до буферизации upload,
  ZIP64 safety, backend dependencies/container и CI с PG/S3.
  Общий LLM cap дополнен резервами для живого диалога и фоновой обработки;
  насыщение и освобождение слотов проверены через настоящий HTTP gateway.
  Ожидание публичной очереди ограничено30с; отключение внутреннего клиента
  отменяет ожидание. Зависшая запись аналитики не удерживает живой чат.

## Отчёт и следующий результат

[Шесть клиентских сценариев: сделано, препятствия backend, образ 10/10 и план](https://github.com/mishanaer/Narra/blob/codex/core-loop-audit-20260904/docs/reviews/core-product-loop-report-2026-09-05.md).

foreground AI без ожидания полной разметки → качество ролей/TTS/сцен →
полная native/live и нагрузочная приёмка.
