# Повторный импорт: кириллица и percent-encoding

## Клиентская ошибка

На Android LOCAL, исходный JS-коммит `6ff8bf5`, собственная книга
`02-мастерская 100%.EPUB` успешно импортировалась по ссылке и открывалась.
После чтения карточка показывала 3%. Повтор тех же байтов создал вторую
карточку без прогресса: результат `Added: 1, updated: 0`.
SHA-256 исходника: `ab9ebf4f20b6e81de165db82d5797a41be564e6d0949f6ac58122be06ffdd4dd`.

Лог импорта показал ENOENT при попытке вычислить hash: RNFS получал
percent-encoded имя вместо настоящего пути. Чтение и копирование через
другой файловый API при этом работали. Импорт продолжался без fileHash,
поэтому повтор не находил прежнюю запись.

## Исправление

Коммит `95d230c`: перед native hash локальный `file:///` преобразуется
в файловый путь с однократным декодированием. Обычный путь и непрозрачный
`content://` не изменяются. `%2520` становится буквальным `%20`, а не пробелом.
Некорректное кодирование не угадывается; best-effort hashing по-прежнему
не блокирует импорт при недоступности провайдера.

## Проверки

- Тесты читают настоящие временные файлы с кириллицей, пробелами, `%` и
  буквальным `%20`; mock native-порта моделирует открытие буквального пути.
- 8 тестов helper PASS; полный мобильный прогон на точном изолированном
  снимке `95d230c`: 179 файлов / 1714 тестов PASS.
- Core: 87 файлов / 697 тестов PASS. Мобильный TypeScript PASS.
- Android dev-client запущен с этим снимком через localhost:8083;
  LOCAL gateway подтверждён как development, библиотека сохранилась.
- На предыдущем снимке собственные EPUB, TXT и PDF импортировались и
  открывали читаемый текст. Это не полная приёмка всех форматов и функций.

## Незакрытые границы

Повторный native-прогон исправления пока не принят. Прогон удаления четырёх
новых QA-карточек выявил отдельный UI-блокер: долгое нажатие показывает лишь
одиночное Remove/Cancel, а режим множественного выбора недостижим.
`LibraryScreen` передаёт обработчик входа и состояние выбора в `BookCard`,
но карточка их не использует. Обход через прямой вызов handler не выполнялся.
Alert закрыт кнопкой Cancel, ни одна книга не удалена. После исправления
этого входа требуется новый импорт → чтение → повтор с сохранением одной
карточки и прогресса. Защищённые книги own01/own27 не удаляются.

Исправление не объединяет ранее созданные дубликаты и не заполняет hash
старых записей автоматически. Активный duplicate index уже использует
`contentHash` наряду с `fileHash`; незакрытый случай — отсутствие обоих.
Для него требуется отдельный безопасный путь сравнения содержимого, без
объединения лишь по названию. Свежий iOS-прогон
этого исправления, произвольные файловые провайдеры и полный AI-loop
не проверены.
