# Подписочный текстовый pipeline: новый живой прогон

На production-коде `61aabb3` выполнена цепочка настоящих workers → PostgreSQL
→ локальный HTTP generator → internal generation service → подписочный Codex CLI.
Node24.20.0, модель gpt-5.6-luna. Все9 точных запросов отдельно прочитаны root
и разрешены по SHA/nonce; автоматических approvals, fallback и повторов внутри
кампании нет. Использован штатный сохранённый вход ChatGPT, без чтения/копирования
credentials. Это соответствует локальному non-interactive использованию из
[официальной документации](https://learn.chatgpt.com/docs/non-interactive-mode#authenticate-in-automation),
но не превращает подписку в общий production API.

## Почему это не полный PASS

CLI harness завершился exit1 уже после публикации: evaluator принимает только
два буквальных названия связи, а корректный entityCandidate здесь — «родство
Анны и Бориса». В диагностической копии после замены только ярлыка обнаружился
следующий отказ: цитата Анны `«Борис, подожди здесь».` дословна, но не совпадает
с двумя представлениями, разрешёнными evaluator. Независимый review подтвердил
обе проблемы проверки. Оригинальный артефакт и evaluator не изменялись,
qualityAccepted=false. Следующий шаг — контрактные регрессии для вариантов
ярлыков/пунктуации с отрицательными примерами подмены участников/слов.

Проверка идемпотентного повтора стоит после evaluator и не выполнилась; её нельзя
засчитать. Позже нужна проверка профилей в реальном мобильном чате: биография
содержит поздние факты, а клиентское ограничение спойлеров здесь не проверяется.
Стили опираются на одну реплику, приветствия общие, appearancePrompt Анны пустой.
Нет изображений, озвучки, native UX или измеренного production SLA. Сохранение
исходников использует memory storage, не S3; PostgreSQL и HTTP настоящие.
