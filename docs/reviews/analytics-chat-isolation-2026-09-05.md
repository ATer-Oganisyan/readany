# Аналитика не должна удерживать живой диалог

Дата: 2026-09-05. Локальное исправление; не результат production soak.

## Причина

Публичные AI routes вызывают `appendInternalEvent`, в том числе через
`requestChat.onAttempt`. Раньше этот callback ждал `eventStore.append` без
предела. Catch обрабатывал отказ, но не никогда не завершающуюся запись.
Таймаут провайдера начинается после начального `onAttempt`, поэтому он не
устранял зависание записи аналитики до обращения к модели.

Независимый read-only probe воспроизвёл: настоящий `requestChat`, зависший
onAttempt, уже отменённый signal, fetchCalls=0, gate active=1/waiting=1.
Это не утверждение, что обычная задержка HTTP-провайдера всегда бесконечна.

## Изменение

Только внутренние продуктовые analytics events проходят через
`createBestEffortEventWriter`: ожидание до100мс, максимум32 незавершённые
записи, без собственной очереди и автоматических повторов. После таймаута
запись может завершиться позднее; её слот остаётся занятым до реального
settlement. При заполнении лимита новые analytics events пропускаются.
Так зависший файловый transport не накапливает неограниченное количество
promise/batches через этот writer и не удерживает LLM permit бесконечно.

Ошибка/таймаут аналитики не меняет успешный продуктовый ответ. При переходе
в degraded state выводятся только причина и счётчики, без содержимого event.
Восстановление успешной записи сбрасывает подавление повторных предупреждений.
Счётчики timeout и persisted могут относиться к одной поздно завершившейся
записи: это не взаимоисключающие категории.

## Проверки и границы

Root: 38 PASS — новый writer, существующие providers, настоящий HTTP-тест
резервов очереди. Новый provider test реально вызывает `requestChat` с
зависшим writer и контролируемым fetch, читает результат, завершает attempt,
освобождает gate. Дополнительно:100 записей после cap не вызывают append;
поздний resolve освобождает место; sync throw/late rejection безопасны;
обычные batches сохраняются без изменения.

Независимое ревью не обнаружило новых дефектов; writer и существующий
event-store:13 PASS. После объединения с queue-deadline исправлением полный
gateway suite в очищенном окружении:831 тест,810 PASS,0 FAIL,21 SKIP
(PostgreSQL/storage integration без настроенной тестовой БД не запускались).
Пропуски не считаются успешной интеграционной приёмкой.

Ограничение относится к internal analytics, не ко всему event ingestion,
не к финансовому journal и не к обязательной записи пользовательских данных.
При деградации часть аналитики теряется намеренно; это должно учитываться
при оценке полноты метрик. Полный HTTP fault injection зависшего диска и
наблюдение деградации под нагрузкой ещё не выполнены.
