# Три чанка, два героя и сохранение родства

## Исправленный продуктовый дефект

Resolver восстанавливал участников явной связи «Анна и Лев — сестра и брат»,
даже когда модель не перечисляла relatedEntityCandidates. Но assembler брал
только исходный список модели и молча удалял эту уже разрешённую связь из
публикации. Теперь он дополняет список ключами resolver, сохраняет порядок
явных участников и исключает неопубликованных персонажей и дубли.

Регрессия проходит через настоящий resolver, нормализатор профиля и assembler:
до правки 0 связей вместо 1; после правки четыре теста PASS. Проверены также
исключённый участник, порядок/дубли и rejected-связь. Строгая проверка полноты
всех связей в validator не добавлена: для групп и лимита 2048 нужна отдельная
спецификация. Исправление не меняет типы или направленность отношений.

## Расширенный worker-тест

`scripts/qa/book-analysis-pipeline-canary.mjs --run-multichunk-mock` использует
собственный фиксированный русский текст, настоящие стандартные чанки
(target4000/min2500/max5000/overlap500), PostgreSQL, все шесть worker factories,
локальный HTTP generation router/client и настоящий внутренний сервис.

Зафиксированный SHA256 текста:
`720f3e6342595211b560e1803c407584ac5cf92287b58c577989a3bcf90814a8`.
Три чанка, два героя, 11 наблюдений, десять завершённых заданий и одна публикация;
девять mock-вызовов: три scan и по synthesis/recall/audit на каждого героя.
Наблюдения в overlap намеренно возвращаются повторно: устраняет дубли настоящий
pipeline, а не mock. Родство передано без готового списка участников.

Проверяется:

- Непрерывное покрытие текста, точные цитаты/offsets, каждый факт ровно один раз.
- Ровно Анна и Борис, сохранённая связь между опубликованными героями.
- Честность Анны, терпение Бориса и поздняя любознательность Анны; нет тревожности
  из единственного поступка. Каждая черта обязана ссылаться на точное утверждение
  именно своего персонажа, не просто на любой существующий evidence ID.
- Ранние personality snapshots не используют позднюю черту или позднюю цитату;
  последний snapshot позднюю черту содержит. Negative controls проверяют и
  ложное раннее значение с формально ранним ID, и ссылку на одиночный поступок.
- Повторный запуск той же редакции не создаёт новую работу/вызовы.

Root: свежая `narra_qa_pipeline_20260905_multi05` вместе со старым window canary
и isolated mixed HTTP smoke: **12 PASS, 0 FAIL, 0 SKIP**. Предыдущие отдельные
multi-прогоны также прошли; собственные строки удаляются finally, диагностическая
схема остаётся. Независимый review усилил negative controls и подтвердил изменения.
Gateway CI теперь создаёт две отдельные свежие БД и запускает эти 12 тестов.

## Чего это не доказывает

Multi-chunk режим пока **строго mock-only**. Старый отдельно утверждаемый live
window-canary сохранён; его четыре вызова не переименованы в тест большой книги.
Новый режим не загружает машинно-зависимый subscription bridge в обычном CI.

Нет реального S3 в этом canary, главного gateway admission/cost ledger, клиентского
импорта, чата, сцен или TTS. В публичном каталоге сейчас намеренно выдаются финальные
traits/description: корректные canonical snapshots сами по себе НЕ доказывают
отсутствие спойлеров у читателя. Alias identity reconciliation отдельно не проверена.

Следующий AI gate: отдельный фиксированный staged-план на девять запросов с
проверкой каждого полного тела, его SHA и предшествующего ответа; затем живой
gold по той же книге. Не расширять существующий четырёхшаговый контроллер просто
повышением лимита, не разрешать автоматические retry/fallback.
