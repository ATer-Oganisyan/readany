Статус: измерено на проде 2026-09-09. Дополняет `docs/work-orders/character-cards-pipeline.md`.

## Что это

Два замороженных gold-набора на русских книгах каталога плюс скорер содержимого карточки.
Gold собран из веб-источников (см. `references[]` в fixtures), счётчики упоминаний посчитаны
по нормализованному тексту той самой редакции, что лежит в нашей БД. Baseline снят с
действующего `book-markup-v3`, поэтому у P1–P4 есть числа, которые новый пайплайн обязан
побить, а не только пороги.

## Как прогнать

```sh
cd services/narra-gateway
node evaluation/fetch-catalog-roster.mjs \
  --base-url https://api.narra.disrupt.builders \
  --book 3c1ab592-0228-4931-ba74-5003fb463c1b \
  --out /tmp/onegin.roster.json --text /tmp/onegin.txt

node evaluation/score-frozen-identity.mjs \
  --fixture evaluation/identity/evgeniy-onegin-ru-v1.json \
  --input /tmp/onegin.roster.json --pretty

node evaluation/score-character-cards.mjs \
  --fixture evaluation/cards/evgeniy-onegin-ru-card-v1.json \
  --identity-fixture evaluation/identity/evgeniy-onegin-ru-v1.json \
  --input /tmp/onegin.roster.json --pretty
```

Судья по внешности и биографии:

```sh
# против настроенной модели
JUDGE_BASE_URL=... JUDGE_API_KEY=... JUDGE_MODEL=... \
node evaluation/judge-character-cards.mjs \
  --fixture evaluation/cards/deti-kapitana-granta-ru-appearance-bio-v1.json \
  --identity-fixture evaluation/identity/deti-kapitana-granta-ru-v1.json \
  --input /tmp/grant.roster.json --out /tmp/grant.verdicts.json --pretty

# пересчёт замороженного baseline без единого вызова модели
node evaluation/judge-character-cards.mjs \
  --fixture evaluation/cards/deti-kapitana-granta-ru-appearance-bio-v1.json \
  --verdicts test/fixtures/deti-kapitana-granta-v3-judge-verdicts.json --pretty
```

`--prompts <dir>` выкладывает промпты на диск, ничего не вызывая, — для ручного прогона.

`fetch-catalog-roster.mjs` регистрирует одноразовую installation ровно так же, как это делает
свежая установка приложения, и дальше только читает.

## Протоколы gold

**Roster.** Персонажем считается сущность, которую источники из `references[]` подают как
действующее лицо именно этого произведения. Список `fanfics.me` по «Детям капитана Гранта»
смешан с «Таинственным островом» и «20 000 лье» (Немо, Сайрус Смит, Пенкроф, Аронакс, Консель,
Нед Ленд, Топ, Неб, Спилет, Герберт) — эти вычищены.

**Счётчики.** `narra-name-endings-v1`: словоформы `основа + NAME_ENDINGS` по границам слов, тем
же правилом, что `packages/app-expo/src/lib/narra/character-name-matcher.ts`, дедуп по offset,
против текста с указанным sha256. Общие фамилии разведены явно: «Гленарван» (1260) минус
«леди Гленарван» (43) → лорд; «Олбинет» минус «миссис Олбинет» → стюард. Неразводимые остатки
лежат в `collisionGuards`, а не в алиасах.

**Significant.** Минимальный убывающий по частоте префикс, покрывающий ≥95 % упоминаний,
с добором частотных ties. Считается только по персонажам, у которых в тексте есть имя
собственное: безымянные (`unnamed: true` — рассказчик, дядя Онегина, муж Татьяны) остаются
в gold, но выведены из гейтового яруса, потому что частотный инвентарь имён до них не дотянется
по построению (риск №1 work order). Границы: Онегин — 3 упоминания, Верн — 55.

**Потолок публикации.** `book-markup-v3` публикует не более 20 персонажей
(`MAX_PUBLISHED_BOOK_CHARACTERS`, отбор `character-frequency-v1`). Полнота по всему gold из 26
сверху ограничена этим потолком, поэтому гейты считаются по significant-ярусу — он в обеих
книгах меньше 20. Это же делает расщепления дорогими: каждая лишняя строка съедает слот.

и тело Ленского, просто Зарецкий и сам появляется в дуэльной главе, так что окно её накрывает.

**Не-персонажи.** Онегин: «Муза» (олицетворение), «Медведь» (зверь из сна Татьяны — с описанием

## Внешность и биография: судья по главным персонажам

Механический скорер видит, что поле заполнено. Он не видит, что «Талькав с умным и спокойным
лицом» — это не портрет патагонца ростом выше шести футов с раскрашенным лицом и в плаще из
шкуры гуанако. Для этого добавлен LLM-судья: он сравнивает карточку с эталонными фактами,
каждый из которых подкреплён дословной цитатой и offset.

Судятся только **главные персонажи**: 5 у Пушкина (Онегин, Татьяна, Ленский, Ольга, Прасковья
Ларина) и 9 у Верна (Гленарван, Элен, Паганель, Мак-Наббс, Джон Манглс, Мери, Роберт, Айртон,
Талькав). Строк больше, чем персонажей: расщеплённые идентичности судятся каждой половиной
отдельно — читатель видит обе карточки.

Правила подсчёта:

- **coverage** — доля core-фактов эталона, переданных карточкой. У расщеплённого персонажа
  засчитывается объединение по всем его строкам: вопрос в том, знает ли продукт факт вообще.
- **contradictions** считаются по каждой строке: карточек читатель видит все.
- **notInGold** — отдельная корзина для утверждений, которые в книге есть, а в эталоне нет.
  Это пробел эталона, и он не штрафует карточку. Так из «выдумок» вышли бобровый воротник
  Онегина и «сёстры милосердия» у постели Мюльреди — оба оборота подлинные.
- **portraitUsable** считается только для персонажей с `describedInText: true`. У Прасковьи
  Лариной внешности в тексте нет, и пустой `appearancePrompt` — правильный ответ, а не провал.

Две книги ломаются в разных местах, и это главный вывод.

**У Пушкина внешность работает, биография — нет.** Костюмные портреты Пушкина ложатся в карточку
почти дословно: Ленский получил «чёрные кудри до плеч» и «красавца в полном цвете лет» (2/2),
Ольга — голубые глаза, льняные локоны и лёгкий стан (3/3), Онегин — стрижку по последней моде,
боливар и бобровый воротник. Ни одной выдумки: там, где Пушкин портрета не даёт (Татьяна,
Прасковья Ларина), карточка ничего не сочиняет — у Татьяны только бледность и распущенные
волосы из сцены письма, у матери `appearancePrompt` пуст.

Биография же — 0.343 при гейте 0.6. У Онегина 2 core-факта из 9: ни рождения на брегах Невы,
ни французского гувернёра, ни дружбы с Ленским, ни письма Татьяны. У Татьяны 2 из 8 — нет ни
романов, ни письма, ни отповеди в саду. Карточка описывает, каков персонаж, и почти не
рассказывает, что с ним произошло. Лучшая биография книги — у матери Лариных (3/5): Ричардсон,
брак без согласия, привычка и самодержавное управление супругом.

**У Верна ломается внешность.** Пять major-противоречий на девять персонажей:

| Персонаж | Что в карточке | Что в тексте |
|---|---|---|
| Джон Манглс | «немного суровые черты лица» | оборот встречается в книге **один раз** и относится к Гленарвану (offset 26 712); портрета Манглса нет вовсе |
| Роберт Грант | «влажные от слёз глаза, маленькое растерянное лицо» | «У него был очень решительный вид» (31 320); слёзы в этой сцене — у сестры |
| Айртон | «суровое, **бесстрастное** лицо; сдержанный взгляд» | «суровое лицо и **блестящие глаза**, глубоко сидевшие под густыми бровями», лицо «умное и энергичное» |
| Мери Грант | «**четырнадцати**летняя» | «Сестре было лет **шестнадцать**» (30 990) |
| Паганель | геральдическая птица на груди | татуировка с последней страницы (1 093 646) |

Первые три — не пропуски, а инверсии: портрет получится противоположным тексту. Портрет
собирается лишь у 3 строк из 11.

**Талькав — самая дорогая потеря.** У Верна это один из самых подробных портретов книги: рост
выше шести футов, широкие плечи, длинные волосы под кожаным ремешком, смуглое лицо, раскрашенное
красным, чёрным и белым, плащ из шкуры гуанако. Карточка: «Талькав с умным и спокойным лицом,
выражающим сочувствие». Покрытие 0 из 4. Портрет по такому паспорту не покажет патагонского
индейца вообще.

**Расщепление рвёт карточку пополам.** У Мери Грант объединённое покрытие внешности 1.00 — но
это две разные строки: «Мисс Грант» несёт полный и точный портрет (16 лет, хорошенькое утомлённое
лицо, скромное и мужественное выражение, бедная но опрятная одежда), а «Мери Грант» — пустой
`appearancePrompt` и возраст, заниженный на два года. У Мак-Наббса та же картина: «Мак-Наббс»
знает возраст и лицо, «Майор» не знает ничего и вдобавок противоречит первой карточке по
характеру. Читатель, открывший «неудачную» половину, видит другого человека.

**Полнота биографии и спойлер-барьер тянут в разные стороны.** У Айртона судья засчитал
`is_ben_joyce` как покрытый core-факт — и он же является нарушением D1. Это не противоречие
в метриках, а точная формулировка задачи P3: биография должна быть полной *в пределах окна*.
Гейт `bioCoreCoverage` поэтому нельзя тянуть вверх, игнорируя `spoilerViolations`, — их надо
брать парой.

### Кто был судьёй в этом прогоне

Baseline-вердикты в `test/fixtures/*-judge-verdicts.json` вынесены **Claude Opus 5** вручную
09.09.2026 по промптам, которые генерирует `judge-character-cards.mjs` (`--prompts`), а не
продовой моделью: локально настроенного LLM-роута нет, а существующий replay ходит к провайдеру
через Docker, который здесь не поднят. Числа выше поэтому — привязка к конкретному судье.
Перед тем как использовать их как гейт в CI, стоит прогнать тот же набор через штатную модель
и сверить: расхождение судей на 0.05–0.1 по coverage — норма, расхождение по
major-противоречиям — повод чинить эталон или промпт.

## Побочная находка: навигации по главам нет

`GET /content/toc` отдаёт **1 элемент** для Онегина («Start») и **2** для Верна («Заглавие» +
название книги). То есть `content_navigation.segments`, на которые опирается D1, для обеих
книг каталога пусты.

Заголовки при этом есть в самом нормализованном тексте: `ГЛАВА ПЕРВАЯ…ОСЬМАЯ` (8 штук) и
`Часть/Глава I…XXII` (67). Fixtures используют именно их — офсеты глав зашиты в
`cards/*.json`, скорер берёт границы окна оттуда.

Практический вывод для P0/P1: как есть, D1 на этих книгах свалится в fallback «окна по 30 000
символов», и спойлер-барьер перестанет совпадать с главой (открытый вопрос №2). Дешевле сначала
починить извлечение заголовков в Prepare, чем строить окна по символам: у Верна 67 заголовков
находятся одной регуляркой.

## Ограничения

1. Gold — из вторичных источников, не из аннотированного корпуса вроде BOOKCOREF. Списки
   Википедии и школьных разборов полны по главным героям и заведомо неполны по эпизодическим;
   поэтому precision по significant считается честно, а полнота по «прочим» — с оговоркой.
2. Счётчики упоминаний посчитаны нашим же правилом стемминга. Для сравнения пайплайнов между
   собой это корректно (правило фиксировано и воспроизводимо), для абсолютной оценки полноты
   матчера — нет: правило и измеряемое совпадают.
3. Спойлерные offsets размечены по первому появлению факта в тексте вручную, по 6 фактам на
   Онегина и 4 на Верна. Это не полный аудит био, а барьерный тест на самые крупные повороты.
4. Baseline снят с прода и заморожен снимками в `test/fixtures/`. При перегенерации разметки
   этих книг числа в тесте разойдутся — это ожидаемо, снимок нужно обновить вместе с baseline.
5. Судья — один, и это Claude Opus 5 (см. выше). Метрики судьи чувствительны к нему и к
   формулировке промпта `character-card-judge-v1`; версия промпта записана в каждый вердикт.
6. Эталон внешности и биографии закрывает только главных персонажей: 5 и 9. Это осознанно —
   у эпизодических лиц ни внешности, ни биографии в тексте почти нет, и судить там нечего.
7. Список core-фактов эталона собран вручную и заведомо неполон: он проверяет, что карточка
   знает главное, а не что она знает всё. Пропуск факта мимо эталона фиксируется судьёй
   в `notInGold`, и это сигнал дополнить эталон, а не оценка карточки.
