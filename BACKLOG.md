# Бэклог Narra

## EAS: автоматизация TestFlight и исправлений

**Добавлено:** 28 августа 2026

**Статус:** идея, объём и порядок внедрения не согласованы

**Референс:** [Clarity — EAS Workflows](https://github.com/SchroederNathan/clarity/tree/main/.eas/workflows).

### Что хотим получить

- **Выпуск в TestFlight.** Проверки кода → сборка → загрузка тестировщикам. При совместимой нативной части использовать repack существующей сборки; при изменении нативной части — полную сборку.
- **Исправление по задаче.** По ручному запуску или согласованной метке GitHub агент воспроизводит ошибку, делает минимальную правку, проверяет результат и открывает PR с доказательствами. Слияние выполняет человек.
- **Исправление по отзыву TestFlight.** Отзывы и сообщения о падениях превращаются в задачи без дублей; очередь передаёт их агенту. Неудачные попытки передаются человеку, без бесконечных повторов.
- **Предпросмотр PR.** После одобрения конкретной версии изменений — отдельный предпросмотр с QR-кодом. Он не обновляет приложение остальных тестировщиков автоматически.

### Что уточнить перед реализацией

- Внедряем всю связку или начинаем с выпуска в TestFlight; какие события запускают каждый сценарий.
- Какого агента используем и какие лимиты времени, повторов и расходов задаём.
- Доступность EAS Workflows, облачных симуляторов, сборок и repack на нашем тарифе.
- Подключение GitHub и App Store Connect; необходимые права и хранение секретов вне репозитория.
- Адаптация к монорепозиторию: приложение находится в `packages/app-expo`, используются pnpm и существующие EAS-профили Narra.
- Для предпросмотров: настройка EAS Update и совместимости версий приложения; отдельное окружение без секретов для кода из PR.
- Изолированные тестовые данные и правила облачной проверки. Текущие правила локального Simulator не менять автоматически.

### Условия готовности

- Workflow проверены по актуальной схеме EAS и прошли отдельно разрешённый пробный запуск.
- Перед выпуском проходят тесты и TypeScript; версии приложения и нативная совместимость проверяются.
- Агент предоставляет доказательства воспроизведения и исправления, не сливает PR и не публикует релизы самостоятельно.
- Нет дублей задач, зависших блокировок очереди или неограниченных повторов; есть понятный способ остановки.
- Автоматические триггеры, облачные расходы и публикации включаются только после согласования.

**Ближайший шаг:** выбрать первый сценарий и согласовать доступы и лимиты. Сейчас это запись в бэклоге, а не включённая автоматизация.
